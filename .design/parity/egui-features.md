# Инвентарь пользовательских функций egui-версии Reward Sounds 1.7.0

Источник: `reward-sounds/` (Rust + eframe/egui 0.29). Прочитано полностью:
`app.rs` (7937 строк), `config.rs`, `tray.rs`, `playback.rs`, `eventsub.rs`, `audio.rs`,
`twitch.rs`, `autostart.rs`, `window_ops.rs`, `main.rs`, `lib.rs`, `http.rs`, `json.rs`,
`logging.rs`, `secure_store.rs`, `theme.rs`, `util.rs`, `icon.rs`, `music/*` (все 11 модулей),
`README.md`, `CHANGELOG.md`, `КАК ЗАПУСТИТЬ.txt`, `tests/audio_smoke.rs`, `assets/overlay.html`.
Ссылки на код даны как `файл:строка` относительно `reward-sounds/src/` (если не указано иное).

Цель документа — матрица паритета для переноса на Tauri. Раздел 13 — «контракт» бэкенда,
раздел 14 — оценка пробелов текущего Tauri-порта (сверено с `reward-sounds-tauri/src-tauri/src/main.rs`
и `core.rs`).

## 1. Экраны и каркас окна

### 13.2 Каналы и способ доставки событий

Все сервисы — «актор + два mpsc-канала»: команды внутрь (`Sender<Cmd>`), события наружу
(`Receiver<Event>`), состояние — `Arc<Mutex<Snapshot>>`. UI **опрашивает** (`poll()`) их в
`update()`: трей, аудио, Twitch, EventSub, музыка — раз в кадр с троттлингом (`app.rs:5828-5858`,
музыка — 200 мс, `app.rs:1099-1103`). Побудка UI: `ctx.request_repaint()` из потоков
(`tray.rs:356-364`, `eventsub.rs:160-163`).

Для Tauri: каналы `Receiver` не сериализуются, поэтому нужен либо опрос из команд
(как сделано в `core.rs`: `drain_events()` + `get_state`), либо `tauri::Emitter`-события из
фонового потока. В egui-версии **нет** единого события «состояние изменилось» — это надо
добавить при переносе, иначе UI будет жить на таймере.

### 13.3 Где хранятся данные

```
%APPDATA%\RewardSounds\            (или $REWARD_SOUNDS_DATA_DIR)
├── config.toml                    настройки + зашифрованные токены DPAPI
├── queue.json                     очередь музыки (если restore_queue)
├── logs\reward-sounds.log         журнал (ротация в .log.1 при 2 МБ, в памяти 400 записей)
├── tmp\                           TEMP для yt-dlp (+ tmp\demo для демо-режима)
└── tools\yt-dlp.exe               один из мест поиска yt-dlp
```
Порядок поиска `yt-dlp.exe`: значение настройки → рядом с exe → `exe\tools\` → `data\tools\` →
`PATH` (`ytdlp.rs:146-182`). Очередь пишется атомарно: `queue.json.tmp` → rename.

### 13.4 Формат `queue.json`

```json
{
  "version": 1,
  "updated_at": "2026-11-16 22:15:35.123",
  "items": [
    {
      "redemption_id": "abc-123",
      "video_id": "dQw4w9WgXcQ",
      "url": "https://www.youtube.com/watch?v=dQw4w9WgXcQ",
      "title": "Название трека",
      "channel": "Канал",
      "duration_sec": 213,
      "user_login": "viewer",
      "redeemed_at": "2026-11-16T22:00:00Z",
      "state": "queued",
      "attempts": 0,
      "error": null
    }
  ]
}
```
`state` — lower-case: `queued|loading|playing|done|failed|refunded|skipped`
(`queue.rs:21-38`). `QUEUE_VERSION = 1` (`queue.rs:15`); несовпадение версии → пустая очередь.
История ограничена `HISTORY_LIMIT = 20` завершёнными (`queue.rs:18`, `357-392`). При загрузке
`playing/loading` → `queued`, завершённые отбрасываются (`queue.rs:322-355`).

## 15. Спорные, скрытые и «мёртвые» места egui-версии

Проверено по коду; при переносе нужно осознанно решить, переносить или выбрасывать.

1. **Мёртвые настройки**: `music.prefetch` и `music.ytdlp_update_days` есть в `Settings`, но не
   имеют UI и **не читаются нигде** (кроме дефолтов). Предзагрузка в сервисе включена всегда
   (`service.rs:738-758`), `YtDlp::update()` (`ytdlp.rs:260`) не вызывается — «автообновление
   yt-dlp раз в N дней» не реализовано, хотя поле и README это подразумевают.
2. `music.ytdlp_path` используется, но UI для смены пути нет — только ручная правка
   `config.toml` (`config.rs:68`, `ytdlp.rs:146`).
3. **OBS-превью с фейковыми данными**: при отсутствии текущего трека в карточке OBS
   показывается демо-строка «ДИНАСТИЯ — Земляк» (`app.rs:4799`) — артефакт демо-режима в
   продакшн-UI.
4. **«Порт оверлея 8770 — свободен»** — текст захардкожен (`app.rs:4861`), даже если порт занят
   (реальная проблема видна только в журнале, `overlay.rs:26-29`).
5. **Оверлей: недоделанный «popup»**. В `assets/overlay.html` есть CSS `.popup/.badge/.ptitle`
   («всплывающая строка заказа», `overlay.html:26-45`), но элементов в DOM нет, а `/state` не
   отдаёт popup-полей (`overlay.rs:106-118`) — задуманный popup при заказе не реализован.
6. **Неиспользуемые UI-помощники** (только объявлены): `quick_start_step` `app.rs:2789`,
   `music_progress` `app.rs:6726`, `duration_label` `app.rs:7737`, иконки `UiIcon::{Edit, Trash,
   Stop, Dots, Plus, External, Folder, Check}` `app.rs:6917-6940`. Признак незавершённых
   задумок (кнопки «стоп», «редактировать», «удалить» на карточках так и не появились).
7. **`MusicService::replay`** (`service.rs:248`, `596-615`) и переменная `replay` в `music_tab`
   (`app.rs:4278`, `4957`) — API есть, кнопки нет. `Snapshot::ready()` (`service.rs:95`) тоже не
   используется (готовность считается в UI, `app.rs:4229`).
8. **`set_redemption_status`** намеренно игнорирует `manual-*` и `*-replay-*` (`app.rs:1162-1164`) —
   за ручные заявки баллы не возвращаются (их и не списывали). При переносе легко потерять, и
   тогда приложение начнёт слать PATCH по несуществующим активациям.
9. **Гонка при смене цены**: `apply_music_price` берёт `title/color` из кэша `remote_rewards` и
   перезаписывает награду целиком (`app.rs:5755-5763`) — если награду изменили в панели Twitch,
   приложение вернёт старые значения. То же в `set_music_reward` (`app.rs:5784-5800`).
10. **Громкости**: общая — 0..1, индивидуальная — 0..2, произведение клампится к 2.0
    (`config.rs:39-41`); при `muted` эффективная 0.0, но ползунки остаются на месте. В Tauri-порту
    `music_set_volume` не синхронизирует `settings.music.music_volume` с сервисом при `muted`
    (проверить при паритете).
11. **Демо-режим** (`REWARD_SOUNDS_*`, `apply_demo` `app.rs:406-554`) — только для скриншотов,
    создаёт WAV в `tmp\demo`, отключает трей/сессию; в Tauri он частично заменён `?screen=`,
    `?obs=1`, `?offline=1` в URL (`app.js:1594-1601`).
12. **Зависимость от заголовка окна**: `window_ops` ищет окно по точному заголовку
    «Reward Sounds» (`window_ops.rs:30-31`). Tauri-окно обязано иметь такой же заголовок, иначе
    `hide_to_tray/show_from_tray` молча ничего не сделают.
13. **Поведение «Свернуть в трей»**: egui не скрывает окно для Windows (уводит в −32000 + 
    `WS_EX_TOOLWINDOW`), чтобы не вставать цикл отрисовки. В Tauri используется `window.hide()` —
    это другая механика (и заодно ломает `FindWindow`-логику из бэкенда, если она вызывается).
14. **Escape/Enter**: Esc в редакторе не срабатывает во время pending-операции
    (`app.rs:3156`), Enter отправляет форму из любого места окна — легко случайно пересоздать
    награду. При переносе стоит сделать «Enter только из поля названия».
15. **Индикатор `занято`**: `busy()` (`app.rs:583-593`) включает тост/сохранение/подключение —
    влияет на частоту repaint. В Tauri аналог придётся сделать иначе (таймер/Tauri-события).
