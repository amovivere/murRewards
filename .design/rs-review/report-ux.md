# UX-аудит: Reward Sounds 1.6.2 (Windows, Rust + eframe/egui 0.29)

**Объект:** `reward-sounds` (Cargo.toml:3 — версия 1.6.2), тёмная монохромная тема, интерфейс на русском.
**Режим:** только чтение. Исходники приложения не изменялись; менялись только файлы этого отчёта в `.tmp/rs-review/`.
**Что изучено:** `src/app.rs` целиком (4602 строки), `src/theme.rs` целиком, а также `main.rs`, `config.rs`, `twitch.rs`, `eventsub.rs`, `playback.rs`, `tray.rs`, `window_ops.rs`, `logging.rs`, `util.rs`, `audio.rs`, `http.rs`, `autostart.rs` — в объёме, нужном для проверки каждой находки.
**Визуальный ориентир:** `00-current.png` + серия живых скриншотов `01-music.png`…`33-user-min-music.png` в этой же папке (сняты параллельно в рамках аудита приложения). Ключевые выводы R01, R09, H02, F02, C02, E09, T03, T09, T11, T13, L01 сверены по этим скриншотам. Скриншоты `docs/*.png` изображают **прежний дизайн** (фиолетово-синяя тема) и текущему коду/теме не соответствуют — как источник не использовались.
**Допущения и ограничения:**
- Приложение не запускалось (чтобы не трогать живую Twitch-сессию в `%APPDATA%\RewardSounds\config.toml`), поведение проверялось по коду.
- Контраст рассчитан по формуле WCAG 2.1 (композит alpha-цветов на фоне), а ширины — по метрикам встроенного `Inter-Regular/SemiBold` из `assets/fonts` (15 px для кнопок, 19.2 SemiBold для заголовков карточек).
- Ширины в egui зависят от DPI-масштаба; дефолт — 100 % (1 logical px = 1 px). Рекомендуется перепроверить выводы R01/V01 на живом окне 980×680 и при 125/150 %.
- Оценки severity: **high** — ломает основной сценарий, риск для стрима/данных или «пользователь не поймёт, что произошло»; **med** — заметное трение, лишние шаги, скрытые состояния; **low** — полировка и консистентность.

## Резюме (TL;DR)

1. **Шапка раздела «Награды» хрупкая по вёрстке и иерархии**: весь ряд (заголовок + 6 действий + статус) требует ≈975 px; в минимальном окне 980×680 доступно 696 px, в дефолтном 1220×840 — 936 px. Переполняется/клипается даже в дефолтном размере (`app.rs:1460-1502`).
2. **Статусы жизненно важных вещей не видны глобально**: упавший EventSub, mute и ошибки подключения не отражаются вне конкретных экранов; единственный глобальный канал обратной связи — один тост в футере на 6–11 с, который обрезается и перезаписывается (`app.rs:267-286`, `1325-1363`).
3. **UI отстаёт от сервера после изменений**: создание/переименование/удаление награды не обновляет список — карточки остаются старыми до ручного «Обновить» (`app.rs:533-580`, `652-674`).
4. **Офлайн-режим прячет всё локальное**: без Twitch нельзя даже увидеть/проиграть/отвязать уже привязанные звуки, хотя данные лежат локально (`app.rs:1521-1531`).
5. **Доступность ниже базовой планки**: несколько текстов 2,1–3,8:1, кастомные контролы без фокуса/скринридера (accesskit отключён в `Cargo.toml:19`), в диалогах нет Esc/Enter/автофокуса, кнопки 12–30 px.
6. **Редактор и подтверждение удаления — немодальные, накладываются друг на друга, фон остаётся активным** (`app.rs:1859-2131`, `update` — `3584-3585`).
7. **Нет поиска/фильтров/сортировки наград** и быстрого способа найти «активные, но без звука»; нет горячих клавиш для «стоп всё» — для стримера это ежедневная боль (`app.rs:1419-1693`, `tray.rs:302-318`).

## 1. Сценарии и точки трения

### С1. Первый запуск, Twitch ещё не подключён
**Шаги:** запуск → вкладка «Награды» → карточка «Twitch не подключён» → «Перейти к подключению» → «Настройки» → Client ID → OAuth device flow → список наград.
**Трения:**
- Онбординг фактически требует создать Twitch-приложение в Developer Console; инструкция отправляет во внешний README и в dev-консоль без пошагового визарда; кнопка **«Подключить Twitch» при пустом Client ID отключена и визуально приглушена, но не объясняет, что нужно ввести** (нет `on_disabled_hover_text`) (`app.rs:2176-2236`, особенно `2211-2218`).
- Копирайт «Подключение занимает пару минут» вводит в заблуждение: для новичка это 10–20 минут с созданием приложения (`app.rs:1525`).
- Ошибки ожидания кода/браузера не персистентны: если браузер не открылся, виджет всё равно пишет «Браузер уже открыт» (`app.rs:2268-2273`), а тост об этом исчезает через 6 с (`app.rs:24-26`).
- На вкладке «Награды» в момент `Busy/Waiting` показывается «Twitch не подключён» и снова CTA «Перейти к подключению», хотя пользователь уже в процессе (`app.rs:1170-1192`, `1521-1531`).

### С2. Подключение Twitch (повторный вход, истёк токен)
**Шаги:** восстановление сессии при старте → фоновый refresh токена → либо «Подключено», либо повторный вход.
**Трения:**
- Во время refresh слева в шапке уже «Подключено · …» (сессия в настройках есть), справа пилюля «Twitch: подключение…» — два противоречащих статуса одновременно (`app.rs:1170-1192`, `1365-1372`).
- При истечении сессии появляется тост 9 с; вкладка «Награды» превращается в «Twitch не подключён», привязки звуков исчезают, а текст реальной ошибки показывается только в «Настройках» (`app.rs:607-618`, `2232-2235`, `2383-2386`). Во время стрима это легко пропустить.
- В «Настройках → Подключение к Twitch» нет понятной диагностики (последняя ошибка EventSub, время последней активации, кнопка «Переподключить» появляется только при не-Listening состоянии — `app.rs:2352-2367`).

### С3. Привязка звуков к наградам
**Шаги:** «Награды» → карточка → «Выбрать звук»/«Заменить» → native-диалог файла → ползунок громкости.
**Трения:**
- Не видно, какие **активные** награды остались без звука: нет фильтра/бейджа «без звука», только стат-карточка «СО ЗВУКОМ» (`app.rs:1506-1517`).
- Уже привязанные звуки невозможно увидеть/потрогать при отсутствии Twitch (`app.rs:1521-1531`).
- Нет отображения длительности файла (только формат и размер), при этом для стрима длина клипа критична (`app.rs:4234-4244`).
- «Убрать» срабатывает сразу, без подтверждения и undo (`app.rs:1698-1704`, `4207`, `4105`).
- Крошечный «▶» (≈12 px) — единственная точка прослушивания; на отсутствующем файле клик молча ничего не делает (`app.rs:4252-4273`).

### С4. Ежедневное использование на стриме
**Шаги:** запуск из трея → проверка «Слушаем награды» → звуки во время эфира → громкость/«Стоп» при инциденте.
**Трения:**
- Нет глобальной горячей клавиши «стоп всё»/«mute» — надо переключиться в окно или лезть в трей (`app.rs:1494-1500`, `tray.rs:302-318`); окно может быть свёрнуто в трей.
- «Стоп» в шапке далеко от остальных действий (RTL-строка ставит его крайним слева, рядом с заголовком), без иконки и подсказки; при отсутствии играющих звуков кнопка приглушена, но без объяснения, почему недоступна (R02).
- Статус EventSub виден только на вкладке «Награды» (H02): если стример ушёл в «Музыку», обрыв прослушивания не виден.
- При скрытии в трей нет уведомления; при `close_to_tray=true` (дефолт, `config.rs:246`) X и Alt+F4 просто прячут окно, а «Выход» есть только в трее → риск «приложение не закрывается» (W01).
- Если награду активировали, а звук не привязан/файл пропал, в интерфейсе это не появляется — только запись в журнале (`playback.rs:101-143`, `app.rs:769-795`).

### С5. Ошибки и обрывы
**Сценарии:** пропал интернет; EventSub переподключается/умер; токен отозван; файл звука переименован; аудиоустройство сменилось; нажали «Выровнять громкость»/«Перезапустить аудио».
**Трения:**
- EventSub: ошибка живёт в `eventsub_error` и показывается только в «Настройках»; на «Наградах» — серый текст «Не слушаем»/«Переподключение…» без деталей и кнопки (`app.rs:719-764`, `1487-1493`, `2352-2367`).
- Загрузка списка: красный блок без «Повторить»/«Переподключить», дублируется тостом; «Обновить» в шапке не показывает загрузку и молча игнорирует повторные клики (`app.rs:1545-1557`, `1464-1469`, `652-656`).
- Файл пропал: на карточке красная строка, но клик по «▶» безмолвствует; нет CTA «выбрать заново» из карточки (C03).
- «Выровнять громкость» способна тихо перезаписать все индивидуальные громкости без предпросмотра/отмены (T04).
- При смене аудиоустройства UI подхватывает его автоматически, но об этом сказано только в мелком hint (`app.rs:2583-2586`), а в шапке/футере статус не меняется.

### С6. Настройки
**Трения:** автосейв без индикации (T02); опасные действия вперемешку с обычными (T03); нормализация без предпросмотра (T04); три пересекающихся «глушилки» (T05); автозапуск всегда стартует в трее, а тумблер «только иконка в трее» об этом не говорит (T06); нет горячих клавиш (T07); нет экспорта/импорта настроек и привязок (T08); в «О программе» противоречивая версия (T09).

### С7. Журнал
**Сценарий:** что-то сломалось → открыть журнал → найти ошибку → отправить в поддержку.
**Трения:** нет фильтров по уровню/поиска; отладочный шум; нельзя выделить/скопировать строку; нет даты (только время); нет связи «ошибка → журнал» из тоста (`app.rs:2737-2828`, `logging.rs:17`, `31-40`).

### С8. Редактирование и удаление награды
**Трения:** диалоги немодальные и могут наложиться; нет Esc/Enter/автофокуса; валидация только после отправки и не рядом с полем; в редакторе нельзя настроить громкость; удаление не сообщает, что локальная привязка звука останется «сиротой»; кнопки в удалении стоят в другом порядке, чем в редакторе (E01–E07).

## 2. Находки

### 2.1. Каркас окна, кастомный title bar, ресайз

**W01 · high · Выход из приложения спрятан: X и Alt+F4 «сворачивают», «Выход» — только в трее**  
`app.rs:3504-3513`, `app.rs:1115-1117`, `config.rs:246`, `tray.rs:302-318`
- **Проблема:** при `close_to_tray=true` (дефолт) закрытие окна перехватывается и уходит в трей без какого-либо уведомления; единственный реальный выход — «Выход» в контекстном меню трея. При этом Windows 11 по умолчанию прячет новые иконки трея в overflow, а balloon-уведомление не реализовано (`tray.rs` использует только `NIF_ICON | NIF_MESSAGE | NIF_TIP`, строки `tray.rs:171`).
- **Почему больно:** пользователь «закрыл» приложение, но оно продолжает работать/подключаться к Twitch; либо наоборот не может завершить процесс, не зная про трей.
- **Решение:** добавить «Выход» в само окно (пункт в сайдбаре под «Система» или в overflow-меню шапки); тултип на X — «Свернуть в трей», при первом закрытии — balloon через `Shell_NotifyIconW` с `NIF_INFO`; опция «Alt+F4 завершает приложение» или Shift+клик по X = выход.

**W02 · med · Окно нельзя тянуть за левую часть шапки; в шапке нет названия приложения**  
`app.rs:3555-3557` (порядок панелей: sidebar → title_bar), `app.rs:1099-1104` (drag-rect = `ui.max_rect()` панели), `app.rs:1231-1238` (сайдбар 236 px)
- **Проблема:** `SidePanel` добавляется раньше `TopBottomPanel::top("titlebar")`, поэтому зона перетаскивания — только 38 px-полоса **справа** от сайдбара. Область с логотипом «R Reward Sounds» выглядит как шапка, но не тянется. Собственного заголовка в кастомном title bar нет вообще.
- **Почему больно:** привычный жест «потянуть за верхнюю левую часть окна» не работает; окно без заголовка выглядит «рамкой без имени».
- **Решение:** строить кастомный тайтлбар на всю ширину (добавлять `TopBottomPanel::top("titlebar")` до сайдбара, логотип+«Reward Sounds» внутрь), зона drag — весь тайтлбар, кнопки окна — исключение.

**W03 · med · Геометрия окна не сохраняется, а возврат из трея принудительно центрирует на основном мониторе**  
`window_ops.rs:60-89`, `window_ops.rs:70-71`, `main.rs:38-46`, `config.rs:213-238`
- **Проблема:** позиция/размер окна нигде не сохраняются; `show_from_tray()` читает текущий размер, но координаты всегда считает от `SM_CXSCREEN/SM_CYSCREEN` (основной монитор). Нижняя граница размера там же задана как 880×620 (`max(880)`, `max(620)`), т.е. код не навязывает объявленный минимум 980×680 (`main.rs:41`) — полагается только на ограничение ОС.
- **Почему больно:** у стримера два-три монитора; окно после каждого сворачивания прыгает на основной монитор, а после перезапуска — в дефолтную позицию.
- **Решение:** сохранять `inner_rect`/позицию в `Settings` (или включить eframe `persistence`), восстанавливать через `ViewportBuilder::with_position/with_inner_size`; `show_from_tray` — только показывать, не менять координаты; нижнюю границу привести к 980×680.

**W04 · med · «Свернуть в трей» из настроек реализована иначе, чем закрытие, и может «заморозить» окно**  
`app.rs:2426-2435`, `app.rs:319-324`, `window_ops.rs:1-6`, `app.rs:344-364`, `app.rs:3496-3590`
- **Проблема:** кнопка «Свернуть в трей» отправляет `ViewportCommand::Visible(false)`, тогда как штатное скрытие идёт через `window_ops::hide_to_tray()` (уводит окно за экран и убирает из taskbar). В `window_ops.rs:1-6` прямо написано, что настоящее скрытие останавливает цикл отрисовки, а все события трея опрашиваются в `update()` (`poll_tray`). Итог: после `Visible(false)` событие «Открыть» из трея некому обработать — окно может вернуться пустым/не интерактивным.
- **Почему больно:** пользователь нажимает безобидную кнопку в настройках и рискует потерять управление приложением.
- **Решение:** заменить на `self.hide_to_tray(ctx)`; удалить прямые `Visible(false)`; один путь скрытия/показа.

**W05 · med · Кнопки окна маленькие, без подсказок и без клавиатурного фокуса**  
`app.rs:1113-1131`, `app.rs:3747-3810`
- **Проблема:** кнопки `38×26` (меньше Windows-стандарта ~46×32), тултипов нет; рисуются вручную (`title_bar_button`), поэтому не имеют `WidgetInfo`/фокус-ринга и не объявляются скринридеру. Maximize/Restore меняет иконку, но нет подписи.
- **Почему больно:** промахи мышью; незрячие/клавиатурные пользователи не могут понять/найти кнопки.
- **Решение:** 46×32, `on_hover_text("Свернуть"/"Развернуть"/"Закрыть")`, `WidgetInfo`/accessible label, фокус-стиль (обводка) при `has_focus()`.

**W06 · low · Невидимые зоны ресайза перехватывают нажатия у краёв и частично поверх кнопок окна**  
`app.rs:1137-1167` (EDGE 10 px, `1142`), `app.rs:1164-1166`
- **Проблема:** `resize_edges` вызывается до отрисовки и на **любое** нажатие в 10 px от края отправляет `BeginResize`. Верхняя полоса 10 px перекрывает верхние 4 px кнопок окна (кнопки `26 px` центрированы в `38 px` тайтлбара), поэтому нажатие у верхней кромки кнопки может начать ресайз вместо клика. Визуальной ручки/утолщения на краях нет.
- **Почему больно:** редкие, но раздражающие «миссы» по кнопкам окна; ресайз обнаруживается только по курсору.
- **Решение:** сузить край до 4–6 px; не начинать resize, если под курсором интерактивный виджет (проверять `ctx.is_pointer_over_area()`/зону тайтлбара); добавить визуальный grip в правом нижнем углу.

### 2.2. Верхняя панель (шапка)

**H01 · high · Три конкурирующих индикатора Twitch и противоречивые состояния**  
`app.rs:1170-1192`, `app.rs:1365-1372`, `app.rs:1444-1453`
- **Проблема:** в шапке слева «● Подключено · {display_name}» (или «Twitch не подключён»), справа — кликабельная пилюля «@{login}» / «Twitch: подключение…» / «Twitch: не подключён», а на «Наградах» ещё и подзаголовок «@{login} · N наград». В состоянии `Busy` (refresh токена) слева зелёное «Подключено», справа оранжевое «Twitch: подключение…» — пользователь видит два взаимоисключающих сообщения.
- **Почему больно:** непонятно, подключён ли Twitch и надо ли что-то делать; дубли занимают место в и без того переполненной шапке.
- **Решение:** один status-cluster в шапке: `● @login` (цвет = состояние) с выпадающим меню (аккаунт, «Открыть настройки», «Переподключить», «Выйти»); левый дубль убрать; логин показывать один раз.

**H02 · high · Вне вкладки «Награды» не видно, слушает ли приложение активации (EventSub)**  
`app.rs:719-726`, `app.rs:1487-1493`, `app.rs:2352-2361`, `app.rs:1325-1363`
- **Проблема:** `EventSubState` отображается только в шапке вкладки «Награды» (мелкий текст + точка) и в карточке Twitch в настройках. В футере, сайдбаре и на вкладках «Музыка»/«Настройки»/«Журнал» статуса нет. Если прослушивание упало (например, `Event::Failed`, `app.rs:757-761`), на других вкладках всё выглядит штатно, а звуки просто перестают играть.
- **Почему больно:** это самый дорогой сбой для стримера — зрители тратят баллы, а звука нет; обнаруживается по чату/жалобам. На живом скриншоте `23-probe-log.png` вкладка «Журнал» при отключённом Twitch выглядит совершенно штатно: ни статуса прослушивания, ни ошибки — только футер «Готово».
- **Решение:** глобальный индикатор в шапке и/или футере: `● Слушаем награды` / `● Переподключаемся` / `● Не слушаем` с tooltip-деталями и кнопкой «Переподключить»; при `Failed` — персистентный баннер (не тост).

**H03 · high · Режим «Без звука» почти невидим, а перетаскивание громкости молча его снимает**  
`app.rs:1198-1218`, `app.rs:2476-2488`, `config.rs:284-287`, `app.rs:2511-2514`
- **Проблема:** при `muted` в шапке остаётся та же цифра (`volume_label()` возвращает `volume`, а не эффективные 0 %), меняется только цвет на `WARN`; нет иконки/слова «Без звука». Движение слайдера принудительно ставит `muted=false` (`app.rs:1214`), при этом никакого сообщения об этом нет. Отдельная mute-кнопка есть только в настройках.
- **Почему больно:** стример думает, что звук включён (видит «80 %»), а награды играют в тишину; или наоборот — трогает громкость и неожиданно «включает» звук.
- **Решение:** иконка динамика с состоянием mute в шапке (клик — mute/unmute); при mute показывать «Без звука» вместо процентов и зачёркнутый динамик; снятие mute по движению слайдера допустимо, но должно сопровождаться явным изменением иконки/подписи.

**H04 · med · Громкость в шапке без семантики: непонятно, что именно регулируется, значение скрыто в слайдере**  
`app.rs:1198-1224`, `app.rs:3385-3403`, `app.rs:2511-2514`
- **Проблема:** подпись «ЗВУК» стоит слева от слайдера (визуально оторвана), 11.4 px, alpha 190 → контраст 3.66:1; `show_value(false)` — слайдер не озвучивает значение (только соседний label). Громкость управляет **только звуками наград**, но музыка имеет отдельный ползунок (`app.rs:3385-3403`), о чём говорит лишь hint в настройках.
- **Почему больно:** пользователь крутит «громкость приложения», ожидая эффекта на музыку; мелкая серая подпись не помогает.
- **Решение:** динамик-иконка + подпись «Звуки наград» (или тултип «Громкость звуков наград; музыка — на вкладке „Музыка“») + значение рядом; включить `show_value(true)` или оставить проценты, но привязать к `Slider::text`.

**H05 · med · Кликабельная пилюля Twitch выглядит как статичный статус**  
`app.rs:1374-1379`, `app.rs:4423-4450`
- **Проблема:** `pill_button` — это `Sense::click()` с hover-инверсией, но визуально в покое читается как бейдж-статус; о кликабельности сообщает только tooltip при наведении. При этом такая же пилюля в «Музыке» не кликабельна вообще (N11).

- **Решение:** добавить шеврон/рамку при hover, либо разделить: статус-текст + явная кнопка «Настройки подключения».

**H06 · low · При отключённом Twitch статус дублируется дважды в одной строке**  
`app.rs:1184-1189`, `app.rs:1371`
- **Проблема:** слева «Twitch не подключён», справа «Twitch: не подключён».
- **Почему больно:** шум; в узком окне каждый лишний элемент вредит.
- **Решение:** см. H01.

### 2.3. Сайдбар

**S01 · med · Служебные подписи и версия не проходят по контрасту**

**S03 · med · Навигация недоступна с клавиатуры предсказуемым образом, hover слишком агрессивный**

### 2.4. Футер, тосты, уведомления

**F01 · high · Единственный глобальный канал обратной связи — один тост в футере, который обрезается, перезаписывается и не виден в трее**

**F02 · med · Футер не выполняет роль статус-строки: «Готово», бренд и неработающая подсказка**  
`app.rs:1339-1361`
- **Проблема:** при отсутствии тоста показывается «Готово» (серый, 3.15:1) или «Аудиовыход недоступен — откройте настройки», но текст **не кликабелен**; справа декоративная надпись «REWARD SOUNDS» (10.2 px alpha 120 → 2.13:1). Статусов подключения/прослушивания/играющих звуков здесь нет.

**F03 · low · Информационные тосты визуально не отличаются от «Готово», различие только по цвету текста**

### 2.5. Экран «Награды»: шапка раздела, статистика, общее

**R01 · high · Ряд из шести действий переполняет шапку: в минимальном окне не помещается с запасом ~270 px**  
`app.rs:1440-1502` (RTL-группа `1460-1502`), `app.rs:3560-3578`, `main.rs:40-41`

Доступно: 980−236−48 = **696 px** в минимальном окне; 1220−236−48 = **936 px** в дефолтном. На живом скриншоте `05-rewards-top.png` (окно 1236×879, контент 952 px) ряд занимает почти всё: заголовок начинается на x=260, кнопка «Создать награду» заканчивается на x=1210 при правой границе контента x=1212 — **запас 1–2 px**. На живом скриншоте `32-user-min-rewards.png` (окно ~980×680, подключён Twitch) видно, как это выглядит: «Стоп» обрезан левым краем, а статус «Слушаем награды» наезжает на заголовок «Награды».

  Строка 1: «Награды» + счётчик, справа `Создать награду` (primary) и `···` overflow.  
  Строка 2 (компактная): поиск, статус-чип «Слушаем награды», `Обновить` (иконка), переключатель вида-сегмент, `Остановить всё` (danger-ghost) — с `ui.horizontal_wrapped()` и скрытием второстепенного в overflow при <1050 px. Обязательно протестировать на 980×680.

**R02 · high · «Стоп» — самое разрушительное действие, но подпись неоднозначна, кнопка стоит отдельно от действий и не объясняет недоступность**  
`app.rs:1494-1500`, `app.rs:4452-4494`, `tray.rs:311-316`
- **Проблема:** подпись «Стоп» без объекта (стоп чего?), без иконки/подсказки/горячей клавиши. В RTL-строке кнопка оказывается крайней слева — рядом с заголовком и далеко от «Создать/Обновить» (на живом скриншоте `05-rewards-top.png` — x≈422–491, т.е. в ~450–640 px от «Обновить»/«Создать награду»). **R03 · high · Статус «Слушаем награды» ничего не сообщает и не даёт действий**  
`app.rs:1487-1493`, `app.rs:719-726`, `app.rs:2352-2367`

Детали ошибки (`eventsub_error`) и кнопка «Переподключить события» есть только в «Настройках». Нет времени последнего события, последней активации, причины остановки. Статус не кликабелен.

- **Решение:** статус-чип с иконкой и иконкой-действием: при ошибке — tooltip с текстом + inline-кнопка «Переподключить»; popover с диагностикой (последнее событие, число активаций за сессию, кнопка «Открыть журнал»). Тот же чип — глобально (H02).

**R04 · med · Переключатель вида «Список/Плитка» называет целевой вид, а не текущий, и не показывает активное состояние**

**R05 · med · Стат-карточки считают разные вещи и выглядят кликабельными, но не кликабельны**  
`app.rs:1506-1517`, `app.rs:1424-1425`, `app.rs:1509`, `app.rs:4524-4546`
- **Проблема:** «НАГРАД» = `rewards.len()` (включая выключенные/недоступные), «СО ЗВУКОМ» = `bindings.len()` (локальные привязки, включая «сирот», которых нет в списке), «ИГРАЕТ» = `playing.len()` (с дублями при повторной активации). Числа между собой не согласованы: «СО ЗВУКОМ» может быть больше числа отображаемых карточек; при офлайне «НАГРАД 0», но «СО ЗВУКОМ 9». Карточки — просто `Frame`, клик не обрабатывается, хотя выглядят как фильтры.
- **Почему больно:** цифры вводят в заблуждение; хочется нажать «СО ЗВУКОМ», чтобы отфильтровать, — не работает.

**R06 · high · Нет поиска, фильтров и сортировки: «какие награды без звука» ищутся глазами**  
`app.rs:1419-1693` (весь экран), `twitch.rs:122-127` (единственная сортировка — доступные сверху)
- **Проблема:** список/плитка рендерятся в порядке Twitch (доступные первыми), без поиска по названию, без фильтров «со звуком/без звука/только активные», без сортировки по названию/цене/дате. При 20–50 наградах основная задача «найти неозвученные/найти конкретную» решается прокруткой.
- **Почему больно:** ежедневная настройка новых наград превращается в ручной перебор; риск пропустить награду без звука.
- **Решение:** панель над списком: `TextEdit` поиска (фильтр по title, debounce не нужен), чипы `Все · Со звуком · Без звука · Активные`, `ComboBox` сортировки (по Twitch/названию/стоимости/наличию звука); счётчики на чипах. Всё считается локально из `remote_rewards` + `settings.twitch_rewards`.

**R07 · high · После создания/изменения/удаления список остаётся старым до ручного «Обновить»**  
`app.rs:533-555` (RewardCreated), `app.rs:556-574` (RewardUpdated), `app.rs:575-580` (RewardDeleted), `app.rs:652-674` (fetch), `app.rs:422/488/498/1673` (все вызовы fetch)
- **Проблема:** обработчики успеха закрывают редактор и показывают тост, но не обновляют `remote_rewards` и не вызывают `fetch_reward_list()`. Созданная награда не появляется в списке, переименованная — показывает старое имя, удалённая — висит мёртвой карточкой (действия по ней будут падать), пока пользователь не нажмёт «Обновить».
- **Почему больно:** пользователь думает, что создание/изменение не сработало, и повторяет действие (создаёт дубликат награды на Twitch); удалённая карточка выглядит как баг.
- **Решение:** после `RewardCreated` — `fetch_reward_list()` (или локально добавить объект); после `RewardUpdated` — обновить элемент в `remote_rewards` (title/cost/color); после `RewardDeleted` — убрать элемент и, при необходимости, очистить локалную привязку/показать orphan. Проверить сценарий «создал → сразу вижу».

**R08 · med · Ошибка загрузки наград не даёт выхода; «Обновить» не показывает состояние загрузки**  
`app.rs:1545-1557`, `app.rs:1464-1469`, `app.rs:515-527`, `app.rs:652-656`
- **Проблема:** красный блок с текстом ошибки — без кнопок; `RewardsUnauthorized` советует «заново подключить Twitch», но кнопки/ссылки нет; кнопка «Обновить» в шапке всегда активна, не меняется на спиннер, а повторные клики во время загрузки молча игнорируются (`fetch_reward_list` early-return при `rewards_loading`). Ошибка параллельно уходит тостом (F01).
- **Почему больно:** тупик: пользователь не знает, что делать после «Не удалось связаться с Twitch».
- **Решение:** inline-баннер с `Повторить` и (при 401) `Переподключить Twitch`, ссылкой «Подробности в журнале»; в шапке — spinner/disabled на время загрузки.

**R09 · med · В офлайне локальные привязки полностью недоступны: нельзя даже прослушать/отвязать/изменить громкость**  
`app.rs:1521-1531`, `app.rs:1545-1664`, `app.rs:1422-1425`
- **Проблема:** при `!connected` рисуется только карточка «Twitch не подключён»; `settings.twitch_rewards` (локальные данные!) не отображаются, хотя стат-карточка «СО ЗВУКОМ» продолжает показывать их количество. Нельзя проиграть звук, поменять громкость, отвязать привязку, удалить «сирот», когда Twitch/интернет недоступны.
- **Почему больно:** интернет пропал посреди стрима — не проверить и не приглушить локальные привязки; после смены аккаунта старые привязки не убрать. На живом скриншоте `20-probe-rewards-disconnected.png` офлайн-экран — это только «Twitch не подключён», стат-карточки 0/0/0 и одинокая кнопка «Стоп» в шапке; ни одной привязки, даже прослушать нельзя.
- **Решение:** офлайн-представление «Локальные привязки» из `twitch_rewards`: имя/файл/громкость, play, «Убрать», без операций с Twitch; сверху баннер «Twitch недоступен — показаны сохранённые привязки» + кнопка «Подключиться». Кэшировать последний список наград в конфиг (id/title) для офлайн-отображения.

**R10 · med · Пустое состояние противоречит наличию кнопки «Создать награду» и уводит в панель Twitch**  
`app.rs:1559-1569`, `app.rs:1461-1463`
- **Проблема:** при пустом списке карточка говорит «Создайте награду в панели Twitch — она появится здесь после обновления списка» и предлагает «Открыть панель наград Twitch», хотя приложение умеет создавать награды само (кнопка «Создать награду» в шапке). Путь «создать → появится после обновления» лишний.
- **Почему больно:** пользователь уходит во внешний браузер и делает лишнюю работу; создание в приложении остаётся незамеченным.
- **Решение:** primary CTA «Создать награду» прямо в пустом состоянии; вторичная ссылка «Открыть панель Twitch»; автообновление после создания (R07).

**R11 · low · «Панель Twitch» открывает браузер без подготовки, после возврата нет автоподхвата**  
`app.rs:1473-1475`, `app.rs:1568`, `app.rs:1682-1684`, `app.rs:23`
- **Проблема:** одно действие называется по-разному («Панель Twitch» / «Открыть панель наград Twitch»), открывает `dashboard.twitch.tv/...` во внешнем браузере без пояснения; после возврата в приложение список сам не обновится.
- **Почему больно:** пользователь не понимает, что его отправили в браузер; приходится вручную жать «Обновить».
- **Решение:** единая подпись «Открыть панель наград Twitch ↗» + `on_hover_text`; при возврате фокуса в окно — автообновление списка (не чаще 1 раза в N секунд).

**R12 · low · Дублирующиеся loading-тексты и счётчик в двух местах**  
`app.rs:1444-1453`, `app.rs:1533-1541`, `app.rs:1507`
- **Проблема:** при загрузке одновременно «Загружаем список наград…» в подзаголовке и «Загружаем награды из Twitch…» со спиннером ниже; счётчик наград дублируется в подзаголовке и в стат-карточке.
- **Почему больно:** визуальный шум; непонятно, какое сообщение главное.
- **Решение:** оставить один индикатор (inline в шапке/на месте списка); подзаголовок — только аккаунт.

**R13 · med · Нет мониторинга активаций и теста цепочки; обычные награды не отмечаются выполненными**  
`app.rs:769-795`, `app.rs:858-880`, `playback.rs:101-143`, `twitch.rs:269-288`
- **Проблема:** активации приходят в `handle_redemption`, но в UI нет ни списка последних активаций, ни счётчика, ни статуса «сыграло/нет звука/файл не найден»: всё уходит только в `log::info`. Если у награды нет звука (`playback.rs:109-115`) или файл пропал (`117-125`), в интерфейсе ничего не появляется. Для **музыкальных** наград приложение обновляет статус активации (`FULFILLED`/`CANCELED`), а для обычных звуковых наград статус не отправляется вовсе (`set_redemption_status` вызывается только из `poll_music`, `app.rs:815-853`), поэтому в панели Twitch такие активации копятся как невыполненные.
- **Почему больно:** стример не понимает, что награда «не звучит»; активации зрителей зависают в очереди Twitch (ручная работа), а зритель может не получить засчитанную награду.
- **Решение:** блок «Последние активации» (5–10): время, зритель, награда, статус звука (✓ сыграно / ⚠ нет файла / — нет привязки), кнопка «Открыть журнал»; «тестовая активация» локально (проиграть как будто пришло событие); добавить авто-`FULFILLED`/`CANCELED` для обычных наград (настройка «Автоматически засчитывать активации»).

### 2.6. Карточка награды

**C01 · high · Длинные названия в режиме списка ломают строку: нет `truncate`, кнопки уезжают**  
`app.rs:4172-4178` (title), `app.rs:4200-4224` (меню и кнопки), `app.rs:4133-4316` (вся карточка)
- **Проблема:** заголовок рендерится как `RichText::new(&reward.title).size(19.2)` в `ui.horizontal` без `.truncate()` и без ограничения ширины. Twitch разрешает до 45 символов (`twitch.rs:158-164`): по метрикам Inter это ≈473 px; плюс меню ≈43 px, «Заменить звук» ≈140 px, «Убрать» ≈47 px и отступы ≈36 px → **≈740 px**, а при минимальном окне содержимое карточки ≈660 px. «···» и правые кнопки вылезают/клипаются. В плитке `truncate` есть (`app.rs:3990-3998`), но без tooltip с полным названием.
- **Почему больно:** именно длинные названия чаще всего встречаются у стримеров; кнопки «Заменить/Убрать»/меню становятся недоступны в узком окне.
- **Решение:** `Label::new(title).truncate()` + `on_hover_text(title)`; ограничить ширину титульной зоны (`ui.set_max_width(...)`), правый кластер кнопок — фиксированной ширины; усечение проверять на 45-символьном названии.

**C02 · med · «···» стоит в середине карточки, имеет размер ~35×30 и прячет «Удалить» без danger-оформления**  
`app.rs:4201-4203`, `app.rs:3890-3913`
- **Проблема:** в списке меню идёт сразу после заголовка (позиция зависит от длины названия): на живом скриншоте `08-list-view.png` «···» стоит примерно на середине карточки (x≈520), а кнопки «Заменить звук»/«Убрать» — у правого края; в плитке «···» — справа сверху. Кнопка — обычный `menu_button` (≈35×30), без доступного имени; в меню «Изменить награду» и «Удалить награду» без разделителя, «Удалить» не выделено цветом. В контексте карточки слово «награду» избыточно.
- **Почему больно:** меню «плавает», опасный пункт легко нажать случайно; на тач-экранах/крупном DPI зона мала.
- **Решение:** фиксированный правый верхний угол, кнопка 32–40 px с `on_hover_text("Действия с наградой")`; разделитель и пункт «Удалить…» цветом `DANGER`; доступное имя для скринридера.

**C03 · high · Прослушивание: крошечный «▶», на отсутствующем файле клик молча ничего не делает, в списке нет подсказки**  
`app.rs:4252-4273` (список), `app.rs:4023-4047` (плитка), `app.rs:4234-4244` («файл не найден»), `app.rs:1384-1415`
- **Проблема:** «▶» — это `Label` с `Sense::click()` (≈12 px), а не кнопка: маленькая цель, нет hover-фона, нет состояния «играет». В списке у него **нет** `on_hover_text` (в плитке — есть, `app.rs:4030`); в списке нет и tooltip с полным путём к файлу (в плитке есть, `app.rs:4047`). Если файл отсутствует, действие не создаётся (`if play.clicked() && exists`), обработчика else нет — клик не даёт ни звука, ни toast, ни открытия выбора файла.
- **Почему больно:** пользователь нажимает play — ничего; не понимает, сломан ли звук/файл/приложение.
- **Решение:** полноценная icon-кнопка 32×32 с `on_hover_text("Прослушать")` и состоянием play/stop; при отсутствии файла — disabled + tooltip «Файл не найден» + клик по строке открывает выбор файла; tooltip с путём в обоих видах.

**C04 · med · Нет индикации «играет сейчас» и остановки отдельного звука**  
`app.rs:4252-4273`, `app.rs:4190-4196`, `app.rs:1509-1516`
- **Проблема:** факт проигрывания виден только как «×N» мелким зелёным в мете (список) или в блоке с баттонами (плитка) и как счётчик «ИГРАЕТ» наверху. Остановить конкретный звук нельзя — только все («Стоп»).
- **Почему больно:** при наложении звуков (активации подряд) невозможно убрать один мешающий, не глуша всё.
- **Решение:** кнопка play/stop на карточке, подсветка «▶ играет» (анимация/иконка), счётчик наложений; per-sound stop в контекстном меню.

**C05 · med · Ползунок 0–200 % без объяснения, без сброса и без итоговой громкости**  
`app.rs:4285-4312` (список), `app.rs:4061-4088` (плитка), `config.rs:39-41`, `config.rs:271-277`
- **Проблема:** диапазон `0.0..=2.0`, подпись «ГРОМКОСТЬ» 10.8 px alpha 200 (≈3.6–3.8:1 на тонированной карточке), значение «133 %». Нет: пояснения, зачем >100 % (компенсация тихих файлов), отметки 100 %, двойного клика/кнопки сброса на 100 %, отображения **итоговой** громкости (мастер × индивидуальная), предупреждения о клиппинге. Пользователь видит 28 % в шапке и 200 % на карточке и не понимает, что услышит.
- **Почему больно:** громкость наград — самый частый тюнинг на стриме; сейчас это «слепое» управление.
- **Решение:** tooltip «Громкость этого звука относительно общей; 100 % — как в файле»; метка 100 %; сброс по двойному клику/иконке; показывать итог (например, «итог 40 %») в tooltip; предупреждение при >100 % («может искажать звук»).

**C06 · med · «Убрать» звук срабатывает моментально, без подтверждения и undo**  
`app.rs:4207-4211`, `app.rs:4105-4109`, `app.rs:1698-1704`
- **Проблема:** отвязка выполняется сразу (`clear_reward_sound`), тост «Звук отвязан от награды.» общего вида; восстановить можно только повторным выбором файла через нативный диалог. Опасная ссылка «Убрать» оформлена ghost-red, на тонированной карточке контраст `DANGER` ≈4.2:1 (ниже AA).
- **Почему больно:** случайный клик разрушает результат выбора файла; для повторной привязки нужен доступ к файловой системе.
- **Решение:** undo в тосте 5–10 с («Отвязано · Вернуть»), второй клик/подтверждение для удаления, либо «Отвязать» в меню «···». Контраст поднять до ≥4.5:1.

**C07 · med · Награды без звука невидимы как класс**  
`app.rs:4275-4281`, `app.rs:4049-4055`, `app.rs:4020-4024`, `app.rs:1559-1569`
- **Проблема:** строка «Звук не выбран» — серый текст alpha 190 (≈3.2–3.4:1), кнопка «Выбрать звук» есть, но бейджа «без звука»/фильтра нет; активная награда без звука выглядит как обычная. При 20+ карточках пропустить такую награду легко.
- **Почему больно:** зритель активирует награду, ничего не слышит и зря тратит баллы.
- **Решение:** бейдж `⚠ без звука` в заголовке карточки, фильтр «Без звука» (R06), счётчик на чипе и, опционально, общий баннер «3 активные награды без звука».

**C08 · low · Карточка не кликабельна целиком; нет длительности файла**  
`app.rs:4133-4316`, `app.rs:4234-4244`
- **Проблема:** ни заголовок, ни мета-строка не являются кнопкой: нельзя открыть редактор/проиграть по клику на строку. Мета показывает имя · формат · размер, но не длительность — для звука награды это ключевой параметр (стример хочет знать, что клип не на 2 минуты).
- **Почему больно:** мелкие цели и нехватка важной информации.
- **Решение:** сделать строку файла кликабельной (play/пауза), заголовок — открытие редактора по двойному клику; добавить длительность (можно кэшировать при выборе файла).

**C09 · med · «Привязки без награды»: появляются только после загрузки списка, нет действия «привязать к другой награде», учитываются в «СО ЗВУКОМ»**  
`app.rs:1592-1612`, `app.rs:1641-1661`, `app.rs:4318-4370`, `app.rs:1509`
- **Проблема:** orphan-карточки рисуются только если `loaded.is_some()`, поэтому при ошибке загрузки списка о них не узнать. В карточке только «Убрать звук» и «Прослушать»; нет «Привязать к награде…», нет громкости. При этом их количество входит в «СО ЗВУКОМ», хотя в списке их нет.
- **Почему больно:** после пересоздания награды на Twitch (новый ID) приходится удалять и привязывать заново; счётчик врёт.
- **Решение:** показывать orphans всегда (даже без списка), добавить «Привязать к другой награде» (диалог выбора), исключить их из «СО ЗВУКОМ» или показывать отдельной метрикой «+N без награды».

### 2.7. Список vs плитка: дубли, потери, пустые состояния

**V01 · high · Плитка жёстко 3 колонки и ломается на минимальном окне**  
`app.rs:3924` (`ui.columns(3, …)`), `app.rs:3962-3964`, `app.rs:4061-4088`, `app.rs:3988-4003`
- **Проблема:** `ui.columns(3)` на любой ширине. При 980×680: контент центра 696 px, колонка ≈226 px, внутренняя ширина карточки ≈194 px. Строка громкости: подпись «ГРОМКОСТЬ» 58 px (9 px font) + слайдер 100 px + «200 %» 32 px + интервалы 18 px = **208 px** → переполнение ≈14 px (слайдер/число клипаются). Название в плитке усекается (хорошо), но без tooltip. При 1220×840 колонка ≈306 px — помещается, но тесно.
- **Почему больно:** официальный минимальный размер окна не поддерживается для плитки; при DPI 125 % (логическая ширина <980 при том же физическом) переполнение наступает раньше.
- **Решение:** адаптивная сетка: 3 колонки при ≥1180 px, 2 при ≥820 px, 1 ниже; считать колонки из `ui.available_width()`; компактная громкость при узкой карточке (иконка + значение, слайдер в tooltip/поповере); добавить tooltip на усечённое название.

**V02 · med · Две независимые реализации карточки (~190 строк каждая) уже разошлись**  
`app.rs:3946-4131` (`reward_card_grid`), `app.rs:4133-4316` (`reward_card`), `app.rs:3916-3943` (`draw_reward_grid`)
- **Проблема:** почти одинаковые данные отрисовываются двумя разными функциями; расхождения уже видны: подписи («Заменить»/«Заменить звук»), состав мета (в плите нет формата/размера), truncate (только плитка), цвет недоступных (плитка приглушает, список нет), позиция «···», tooltip пути (только плитка), alpha `DANGER`.
- **Почему больно:** любая правка (новая кнопка, состояние «играет», длительность файла) требует двух изменений и снова расходится; баги воспроизводятся по-разному в видах.
- **Решение:** один компонент `RewardCardUi` с `ViewMode { Grid, List }` (density prop) и общим `RewardCardModel` (title, cost, state, binding, playing, missing). Список/плитка — только раскладка.

**V03 · med · Что теряется/дублируется между видами**  

| | Список | Плитка |
|---|---|---|
| Заголовок | полный, без truncate → ломает строку (C01) | truncate без tooltip |
| Файл | имя · формат · размер, без пути/tooltip (C03) | только имя, tooltip пути есть |
| Недоступная награда | цвет текста не приглушается | приглушается (`TEXT_DIM`) |
| Кнопки | «Заменить звук» + «Убрать» справа | «Заменить» + «Убрать» снизу |
| «···» | после заголовка, «плавает» | справа сверху |

**V04 · low · Разная логика секции «Выключенные и недоступные награды»**

### 2.8. Редактор награды и подтверждение удаления

**E01 · high · Диалоги не модальные: фон остаётся активным, диалоги могут наложиться друг на друга**  
`app.rs:1887-1896` (редактор: `anchor(CENTER_CENTER)`, `movable(false)`), `app.rs:2092-2096` (удаление: `anchor(CENTER_CENTER)`, без `movable(false)`), `app.rs:3581-3585` (оба рисуются в одном кадре), `app.rs:4201-4204`/`3892` (меню карточек остаётся доступным)
- **Проблема:** оба окна — обычные `egui::Window` без затемнения и без блокировки фона: под диалогом можно нажимать кнопки шапки, менять вид, крутить громкость и даже открыть второй диалог (меню «···» → «Удалить награду») поверх редактора. Оба центрируются в одну точку → наложение. В egui 0.29 готового `Modal` нет (в `egui-0.29.1/src/containers` нет `modal.rs`), поэтому нужна ручная реализация.
- **Почему больно:** пользователь может случайно изменить данные под диалогом или удалить награду, которую редактирует; непонятно, что заблокировано.
- **Решение:** один переиспользуемый модальный контейнер: `egui::Area` на весь экран с полупрозрачным фоном (`Color32::from_black_alpha(160)`), перехватом кликов, затем `Window`/`Area` с контентом поверх; при открытии второго диалога — закрывать/ставить в очередь. При обновлении egui — перейти на `egui::Modal` (0.30+).

**E02 · high · Нет клавиатуры в диалогах: Esc/Enter не работают, поле названия не получает фокус, фокус невидим**  
`app.rs:1859-2081`, `app.rs:2084-2131`, `app.rs:4452-4494`, `app.rs:4496-4522`
- **Проблема:** во всём `app.rs` нет обработки `Key::Escape`/`Key::Enter` и нет `request_focus()` (проверено grep по исходникам). При открытии редактора курсор не в поле «НАЗВАНИЕ» — печатать нельзя, пока не кликнешь. Esc не закрывает, Enter/Ctrl+Enter не отправляет. Кастомные кнопки «Отмена»/«Создать» рисуются вручную и не показывают фокус, хотя `Sense::click` делает их фокусируемыми (Tab). В состоянии `pending` кнопка «Отмена» **выглядит полностью активной, но её обработчик подавлен условием `clicked() && !editor.pending`** — клик ничего не делает (`app.rs:2062`).
- **Почему больно:** для мыши пользователя — лишний клик; для клавиатуры/скринридера — диалог фактически недоступен, невозможно понять, где фокус.
- **Решение:** `if ctx.input(|i| i.key_pressed(Key::Escape)) { cancel }`; Enter в поле названия = submit (Enter в многострочных — нет), Ctrl+Enter — везде; `title_edit.request_focus()` на первом кадре; `default` кнопка с фокус-рингом; `on_disabled_hover_text` для заблокированной отмены.

**E03 · high · Валидация только по кнопке, ошибка в общем блоке, счётчика символов нет; тексты проверок расходятся с кодом**  
`app.rs:1915-1920` (`char_limit(45)`), `app.rs:1772-1792` (`draft.validate()` при submit), `app.rs:2039-2051` (общий красный блок), `app.rs:966-971` и `config.rs:151-154` (Client ID: «примерно 30» vs `len >= 20`), `app.rs:2197` (hint «30 букв и цифр»)
- **Проблема:** пустое название/превышение лимита пользователь узнаёт только после нажатия «Создать/Сохранить», ошибка показывается единым блоком внизу, а не под полем; `char_limit(45)` молча не даёт печатать дальше (нет счётчика «12/45»); валидация Client ID в тексте ошибки говорит «примерно из 30 букв», hint — «30 букв и цифр», а фактическая проверка — `>= 20` alnum (`config.rs:151-154`).
- **Почему больно:** непонятно, что именно не так и где; пользователь бьётся в лимит без обратной связи; разные тексты про Client ID подрывают доверие.
- **Решение:** inline-ошибка под полем + красная рамка поля + фокус на первое невалидное; счётчик «0/45» справа от поля; ошибки по мере ввода (после первого submit); единый текст правил Client ID («латиница и цифры, 20–30 символов») и в hint, и в ошибке.

**E04 · med · «Прослушать» в редакторе игнорирует индивидуальную громкость и режим mute, не останавливается**  
`app.rs:2022-2031`, `app.rs:1878`, `app.rs:1400-1410`
- **Проблема:** превью играет `engine.play("__editor_preview__", path, master_volume)`, где `master_volume = effective_volume()` (0 при mute). Индивидуальная громкость привязки не учитывается, поэтому превью не соответствует тому, что услышит зритель; повторный клик не останавливает, индикации «играет» нет; при mute превью молчит без предупреждения (в отличие от `start_playback`, где есть toast — `app.rs:1405-1410`).
- **Почему больно:** стример настраивает звук «на слух» и получает другое звучание в бою.
- **Решение:** превью через `effective_sound_volume` (для новой награды — мастер), кнопка-переключатель Play/Stop, подсветка, при mute — понятное предупреждение/предложение снять mute.

**E05 · med · В редакторе нельзя настроить громкость звука**  
`app.rs:1960-2037` (секция «ЗВУК НАГРАДЫ»), `app.rs:4285-4312` (громкость на карточке)
- **Проблема:** в редакторе выбирается файл, но ползунок громкости живёт только на карточке. Пользователь, который «настраивает награду», ожидает увидеть там все её параметры.
- **Почему больно:** после создания приходится закрыть редактор и найти карточку, чтобы выставить уровень; лишний цикл.
- **Решение:** добавить в секцию «ЗВУК НАГРАДЫ» ползунок 0–200 % + «Прослушать», синхронизированный с привязкой (для новой награды сохранять до появления ID — например, в `pending_created_sound` расширить до структуры с громкостью).

**E06 · med · Подтверждение удаления несогласовано с редактором и не предупреждает о судьбе локальной привязки**  
`app.rs:2084-2131`, `app.rs:1841-1856`, `app.rs:575-580`
- **Проблема:** у окна удаления есть стандартный title bar (в отличие от кастомного редактора), оно `movable`, кнопки идут `Удалить` → `Отмена` слева-направо (в редакторе primary — справа), нет Esc/Enter/фокуса; текст «Действие необратимо» относится к Twitch, но не сказано, что локальная привязка звука останется (станет «сиротой», `app.rs:1592-1611`). В коде `confirm_reward_delete` не вызывает `clear_reward_sound`.
- **Почему больно:** пользователь удаляет награду и не понимает, почему звук и счётчик «СО ЗВУКОМ» остались; случайное удаление необратимо и без явного danger-оформления.
- **Решение:** единый стиль модалки; «Отмена» слева, «Удалить навсегда» справа (danger fill), фокус на «Отмена»; текст «Награда исчезнет у зрителей. Локальная привязка звука останется — её можно будет удалить» + чекбокс «Удалить и привязку звука»; Esc/Enter.

**E07 · med · Ожидание запроса до 25 с без отмены: «Отмена» заблокирована, но выглядит активной**  
`app.rs:1820`, `app.rs:2053-2069`, `http.rs:18`
- **Проблема:** после submit `reward_busy = true`, кнопка «Отмена» отключена только логическим условием `clicked() && !editor.pending`, а не через `add_enabled_ui`, поэтому egui не приглушает её: визуально это полностью активная кнопка, клик по которой ничего не делает (см. E02). HTTP-таймаут 25 с (`http.rs:18`), в UI — только спиннер, без «Создаём награду на Twitch…» и без возможности прервать. Если запрос завис, диалог нельзя закрыть.
- **Почему больно:** в плохую сеть пользователь застревает в диалоге на полминуты и не знает, идёт ли операция.
- **Решение:** отключаемая по-настоящему (приглушённая) «Отмена»/«Закрыть» с логикой «запрос уже отправлен — дождитесь ответа», текст статуса, таймер; при таймауте — понятная ошибка с «Повторить».

**E08 · low · Копирайт редактора: «Награда сразу появится у зрителей» неточно и не предупреждает о включении**

`theme.rs:81` (`extreme_bg_color = #101010`), `theme.rs:14` (`PANEL = #0E0E0E`), `theme.rs:104-106` (`widgets.inactive.bg_stroke = TRANSPARENT`), `app.rs:1915-1920` (TextEdit названия), `app.rs:1930-1955` (DragValue стоимости и цвет)

- **Решение:** шкала 12/13/14/16/20/24/28/36 и 4–5 именованных стилей (`Small`, `Body`, `Label`, `SectionTitle`, `H1`), перевести `.size()` на `TextStyle`; alpha — только для фонов, текст — из токенов.

**A07 · low · Только жёсткая тёмная тема: нет учёта системного high-contrast и масштаба интерфейса**  
`theme.rs:43-147`, `theme.rs:77-127`
- **Проблема:** `apply()` всегда ставит `Visuals::dark()` с фиксированными цветами; настройки «светлая тема/контраст/масштаб UI» отсутствуют; Windows-режим высокой контрастности игнорируется.
- **Почему больно:** пользователи с нарушениями зрения не могут адаптировать интерфейс.
- **Решение:** как минимум уважать системный high-contrast (или дать альтернативную палитру), добавить настройку «Масштаб интерфейса 100–150 %» (`ctx.set_pixels_per_point`).

**A08 · low · Нет tooltip'ов у ряда иконочных и статусных элементов**  
`app.rs:1113-1131` (min/max/close), `app.rs:4252-4263` («▶» в списке), `app.rs:1487-1493` (статус), `app.rs:1309-1320` (звук готов), `app.rs:4431` (пилюля без явного аффорданса)
- **Проблема:** часть иконок/статусов не имеет `on_hover_text`; в плитке у «▶» tooltip есть, в списке — нет; у кнопок окна — нет совсем.
- **Почему больно:** непонятные иконки и статусы при первом знакомстве.
- **Решение:** единое правило: любой иконочный контрол и статус — с tooltip; для статусов — с расшифровкой и действием.
