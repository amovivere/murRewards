# Reward Sounds: что добавить дальше

**Коротко.**
- Приложение уже закрывает «звук за баллы», музыку и оверлеи. Не хватает **видимой реакции** для зрителя и **управления без переключения окон**.
- Три главные ставки: награда-сценарий (движок действий), алерты + TTS, пульт (панель, хоткеи, OBS).
- Сначала — дешёвая безопасность звука (v1.8), потом видимый скачок (v2.0).

**Контекст.** Изучен текущий код (`reward-sounds/`, `reward-sounds-tauri/`), README и материалы `.design/`. Версия интерфейса — 1.7.0. Это не ТЗ, а карта возможностей: что даст стримеру больше всего пользы, что реально сделать **локально** и в каком порядке.

---

## 1. Что уже есть

| Слой | Готово | Что это открывает |
|---|---|---|
| Twitch | OAuth + refresh, EventSub на активации наград, CRUD наград | Любые события канала и действия от имени канала |
| Звук | rodio, микс нескольких звуков, громкость 0–200 %, нормализация, тест, рестарт | Звуковая панель, TTS, лимитер, очередь звуков |
| Музыка | yt-dlp, очередь, предзагрузка, возвраты баллов, cookies, пауза Яндекс Музыки | Радио, crossfade, ducking, поиск по названию |
| Оверлеи | HTTP `127.0.0.1:8770`, `/overlay`, `/chat-overlay`, настройки, живое превью | Алерты, виджеты, пульт, второй экран |
| Оболочка | Трей, автозапуск, single-instance, геометрия окна, журнал, здоровье, онбординг | Фоновая работа и диагностика |
| UI | React, дизайн-система, один desktop-лэйаут 1600×1000 | Быстрое добавление экранов |

**Чего нет:** алертов, озвучки (TTS), звуковой панели, глобальных хоткеев, OBS WebSocket, статистики, действий награды кроме звука, отправки в чат (есть только анонимное чтение `!трек`), бэкапа.

**Ключевая деталь:** приложение уже умеет играть звук на активацию. Зритель его слышит (если OBS захватывает рабочий стол), но **не видит, кто и за что** его вызвал. Это главный незакрытый разрыв.

---

## 2. Главный вывод

Приложение прошло путь «проигрыватель звуков → пульт музыки и оверлеев». Следующий шаг — **замкнуть событие**:

> зритель активировал награду → он это увидел, услышал и понял; стримеру не нужно переключать окно.

Локальность — это преимущество, а не ограничение: задержка в миллисекундах, приватность, работа без облака, доступ к локальным файлам, OBS и аудиоустройствам, отсутствие подписки. Не нужно превращаться в чат-клиент или в OBS — нужно стать **клеем** между ними.

Формула: **событие → действие → видимая реакция → запись**. Один движок действий, одна шина событий, один локальный сервер оверлеев.

---

## 3. Ставка №1. Награда-сценарий (движок действий)

Сейчас награда = один звук. Предложение: награда = **список действий**, которые выполняются по порядку.

Примеры:

- «Озвучь меня» (500 баллов): TTS текста зрителя → алерт с ником → музыка тише на 8 секунд → счётчик «озвучек» +1.
- «Смена сцены» (1000): сцена OBS «Караоке» → алерт → через 60 секунд вернуть «Игра».
- «Клип!» (2000): сохранить replay buffer → показать алерт → открыть папку с клипом.

**Действия MVP:** звук, алерт, TTS, сцена/источник OBS, клип, сообщение в чат, инкремент счётчика, пауза.

**Модель:** `RewardBinding { reward_id, actions: Vec<Action>, cooldown_sec, max_per_user, enabled }`. Старое `RewardSound` мигрирует в `actions: [Sound]` — конфиг версионирован, миграция с бэкапом.

**UI:** карточка награды → «Действия»: список, добавить/удалить, порядок, тест, пресеты «Мем», «Озвучка», «Сцена», «Клип». Не визуальный node-graph — это территория Streamer.bot.

**Почему это главное.** Отдельные фичи (алерты, TTS, OBS) без движка остаются набором кнопок. Движок превращает их в комбайн без комбайна: стример собирает сценарий один раз.

**Локально:** полностью. Действия с OBS — через локальный WebSocket.

**Сложность:** L, но первые три действия — M.

**Риск:** частичное выполнение (звук прошёл, сцена — нет). Показывать результат по каждому действию, не откатывать уже случившееся, возвращать баллы только при ошибке **до** первого действия. Таймауты и отмена по «Стоп всё».

## 4. Ставка №2. Алерты

Зритель должен видеть причину звука.

- **События:** follow, sub/resub/gift, cheer, raid, активация награды. Сейчас EventSub слушает только активации наград.
- **Очередь алертов:** не перекрывать друг друга, максимальная длительность, «пропустить», тихий режим, приоритет (рейд > саб > награда).
- **Страница `/alert`:** ник, тип события, награда/сумма, аватар, анимация, длительность. Звук играет приложение, страница — только визуал, чтобы в OBS не было двойного звука.
- **3–4 пресета** (Neon / Minimal / Retro) + настройки: длительность, шрифт, позиция, цвет, «показывать только награды».
- **Тест**, «Показать сейчас», журнал алертов.
- **Задержка OBS:** опция «задерживать алерты на N секунд» — позже.

**Почему.** Сейчас награда — «слепое» событие: зрители слышат звук, но не понимают, что происходит. Алерт объясняет звук и превращает награду в мини-шоу. Это самый заметный шаг для зрителя при умеренной сложности.

**Локально:** EventSub + страница на 8770 + аудиодвижок.

**Сложность:** M.

**Риск:** новые scopes и одна переавторизация; не мешать StreamElements, если он уже стоит (режим «только награды»); потеря событий при перезагрузке OBS — очередь должна переживать переподключение; кастомизация не должна стать конструктором.

## 5. Ставка №3. TTS — озвучка за баллы

- **Источники:** текст награды, `!tts`, алерты, позже донаты.
- **Движок:** Windows SAPI (офлайн, системные голоса, русский) на отдельном STA-потоке → WAV → аудиодвижок. Опционально Piper для качества.
- **Очередь:** лимит длины, кулдаун на пользователя, блок-лист, «прочитать ник», громкость, «пропустить озвучку».
- **Ducking:** музыка тише на время TTS, потом возврат.
- **Фильтр:** мат, оскорбления, ссылки, спам-паттерны.

**Почему.** «Озвучка за баллы» — проверенный формат вовлечения. Локально это бесплатно, без облачных лимитов и без отправки текста зрителей на чужой сервер. Прямое расширение «звуков за баллы».

**Локально:** да, полностью.

**Сложность:** M.

**Риск:** качество SAPI (робот — можно подать как фичу), русского голоса может не быть в системе — подсказать, как добавить; COM/STA; очередь; ложные срабатывания фильтра.

## 6. Ставка №4. Пульт: панель, хоткеи, мини-окно, OBS

### 6.1 Звуковая панель

- Сетка 12–24 пэдов: файл, цвет, иконка, громкость, loop, хоткей.
- Категории, поиск, drag&drop, «Стоп всё».
- «Бип-цензура» (встроенный тон), ночной режим.
- Мини-окно always-on-top: 6 пэдов + «сейчас играет» + стоп.

### 6.2 Глобальные хоткеи

- Стоп всё, mute, skip, пауза заявок, сцена, клип, пэд.
- Tauri global-shortcut, запись комбинации, проверка конфликтов.
- По умолчанию выключены; «только когда окно активно» — для безопасных действий.

### 6.3 OBS-мост (obs-websocket v5)

- Подключение `localhost:4455`, пароль, статус, переподключение.
- Сцены, источники, mute, запись/стрим, replay buffer, переходы.
- Использование: действие награды, хоткей, кнопка «BRB», авто-сцена при старте, проверка «оверлей добавлен», «звук доходит до OBS» (аудиометр).
- Клипы: сохранить replay buffer, имя, список, открыть папку, главы для YouTube.

**Почему.** Убирает alt-tab и превращает приложение в пульт. «Клип за баллы» — это контент, который иначе делают руками.

**Локально:** да.

**Сложность:** M.

**Риск:** версия OBS, пароль, порт; частичные ошибки; не блокировать UI; понятные ошибки вместо «OBS недоступен».

## 7. Ставка №5. Звук, который не сорвёт эфир

Это дешёвые, но очень заметные улучшения — их стоит сделать до крупных фич.

- **Лимитер и нормализация:** мастер-лимитер, потолок, мягкий клип, fade in/out; «не громче N %».
- **Очередь звуков:** максимум N одновременно, глобальный и пер-награда кулдаун, лимит на пользователя, приоритет модераторов, тихие часы. Пример: два звука играют, третий ждёт 3 секунды; если не успел — активация отменяется с возвратом.
- **Возврат баллов:** если файл пропал, формат не поддержан или аудиоустройство недоступно — отменить активацию (CANCELED) и вернуть баллы, показать тост и запись в журнале. Опция «возвращать всегда при ошибке».
- **Ducking:** музыка тише под TTS и алерты.
- **Диагностика:** «слышат ли зрители?» — тест + подсказка про OBS Desktop Audio / виртуальный кабель.

**Почему.** Сейчас 20 активаций могут наложиться друг на друга; битый файл = потерянные баллы; громкий звук = боль в наушниках и жалобы. Это фундамент доверия к приложению.

**Локально:** да.

**Сложность:** S–M.

**Риск:** лимитер меняет звук (нужен bypass), кулдауны раздражают чат (настройки), возврат требует прав на управление активациями.

## 8. Быстрые победы

- **Виджеты:** uptime, countdown/BRB, счётчик активаций, цель по фолловерам/сабам, очередь, now playing. Один `/widget?id=...`, конфиг в приложении.
- **Музыка 2.0:** локальное радио при пустой очереди, crossfade, история и антиповтор, лимит заказов на зрителя, поиск по названию, vote skip.
- **Статистика эфира:** события в JSONL, итоги после стрима (топ наград, уникальные зрители, возвраты, ошибки), экспорт CSV/MD.
- **Бэкап и паки:** экспорт без токенов, авто-бэкап, импорт с валидацией, «звуковой пак» с файлами.
- **OBS-сцена-шаблон:** готовый JSON scene collection + инструкция (Starting / Game / BRB / Ending + оверлеи).
- **Массовое создание наград** из папки звуков (имя файла → награда) с подтверждением и учётом лимитов Twitch.

---

## 9. Позже (M–L, с оговорками)

- **LAN-пульт на телефоне:** `/remote`, токен, QR, только локальная сеть, firewall, отключение по таймауту. Не открывать в интернет.
- **Локальный API / WebSocket** для Stream Deck, Streamer.bot, AutoHotkey. Токен, только localhost, документация.
- **Авто-сцены по активному окну/игре**, расписание, «стрим начался/закончился» (EventSub `stream.online/offline`).
- **Колесо розыгрыша и рулетка**, розыгрыши по ключевому слову; осторожно с гемблинг-оптикой.
- **Донаты** (DonationAlerts / DonatePay) — внешние API, это уже не «локально»; битсы и cheers — локально через EventSub.
- **Мультиплатформа** (YouTube / Trovo / VK Play) — внешние API, отдельный адаптер.
- **Локальная экономика и магазин** — только если реально нужна: Channel Points у Twitch уже есть.

## 11. Рекомендуемые релизы

**v1.8 «Не сорви эфир» (2–3 недели).** Лимитер, очередь и кулдауны звуков, возвраты баллов, ducking, бэкап, статистика v1. Без новых scopes и без OBS — минимальный риск. Заодно появляется шина событий и аудиошины, на которых держится всё остальное.

**v2.0 «Эфирный пульт» (2–3 месяца).** Движок действий, алерты, TTS, звуковая панель и хоткеи, OBS-мост и клипы, виджеты. Здесь нужна одна переавторизация Twitch и настройка OBS, зато это видимый скачок для зрителя.

**v2.1 «Вовлечение».** Колесо и розыгрыши, цели, музыка 2.0 (радио, crossfade), статистика v2, шаблоны сцен.

**v3.0 «Экосистема».** LAN-пульт, локальный API и Stream Deck, авто-сцены и расписание, донаты, мультиплатформа.

Почему так: v1.8 снимает реальные риски и создаёт фундамент; v2.0 даёт самый заметный результат; v2.1 добавляет вовлечение; v3.0 — интеграции, где выше цена ошибки и поддержки.

## 12. Чего не делать

- **Полноценный чат-клиент и модерация.** Команда уже отказалась от встроенного чата; Nightbot и StreamElements делают это лучше, а поддержка съест продукт. Максимум — «отправить сообщение в чат» как действие награды.
- **Замена OBS:** захват экрана, сцены, кодирование, микширование.
- **Своя донат-платформа и платежи.**
- **Облачный аккаунт, синк и маркетплейс** — это ломает локальность и приватность.
- **Визуальный node-graph** — территория Streamer.bot; здесь пресеты и понятный список действий.
- **Мультиканальность и команда.**
- **Мобильное приложение** — LAN-веб-пульт закрывает сценарий дешевле.

## 13. Как это встроить в интерфейс

Не добавлять по вкладке на фичу. Предложение:

```
ОСНОВНОЕ    Награды · Музыка · Эфир · Оверлеи
ЭФИР        Алерты · Панель · Виджеты · Сцены
СИСТЕМА     Настройки · Журнал
```

- «Награды» остаются домом для действий: карточка → «Действия».
- «Эфир» — один раздел с сегментами, а не четыре вкладки.
- «Оверлеи» — все URL и превью (чат, алерт, виджеты) в одном месте.
- Онбординг превращается в чеклист: подключить Twitch → привязать звук → добавить оверлей в OBS → проверить алерт → включить хоткей.

**Ограничение:** текущий UI рассчитан на 1600×1000 без адаптива. До v2.0 нужен минимум 900×620 и компактный режим, иначе новые экраны усилят старую проблему.

## 14. Технические заметки

- **Единая шина событий.** `AppEvent` (Redemption, Follow, Sub, Cheer, Raid, TrackQueued, SoundFailed, AlertShown…). Журнал, тосты, статистика, алерты и оверлеи — подписчики. Это убирает разрозненный polling и делает возможными алерты и статистику без дублирования логики.
- **Конфиг v2.** `RewardBinding { actions }`, миграции, `version`. Бэкап без токенов, валидация импорта, откат при ошибке миграции.
- **Оверлеи.** Один `/state` + опционально SSE `/events`; cache-busting через `?v=`; страницы без внешних CDN (работают офлайн); по умолчанию bind только `127.0.0.1`.
- **Безопасность локального HTTP.** Сейчас сервер только читает состояние. Как только появятся действия (стоп, сцена, клип), нужен токен, проверка `Origin` и `Host`, запрет wildcard CORS. Иначе любой сайт в браузере сможет дёрнуть localhost.
- **Аудио.** Три шины: music / sfx / voice + мастер-лимитер. Ducking — отдельный множитель, чтобы не перетирать громкость пользователя. Не декодировать весь трек в память (существующая проблема) — потоковое декодирование или чанки; кэш TTS для частых фраз.
- **Twitch.** Новые EventSub-подписки и scopes → один понятный поток переавторизации; деградация по подписке (нет прав на follows — алерт не показывается, остальное работает); бэкофф и лимиты.
- **OBS.** `tungstenite` в фоновом потоке, корреляция запросов, таймауты, reconnect; пароль в DPAPI; не блокировать UI.
- **TTS.** STA-поток, SAPI; fallback eSpeak/Piper; лимит длины; очередь; кэш.
- **Хоткеи.** `tauri-plugin-global-shortcut`; проверка конфликтов; по умолчанию выключены.
- **Данные.** JSONL событий + ротация; агрегаты по сессиям; приватность ников — опция «не сохранять».
- **Тесты.** Юнит-тесты исполнителя действий, очереди и возвратов, миграции конфига; контрактные тесты оверлеев; существующие UI-смоук-тесты.

## 15. Метрики

- Время до первого видимого алерта у нового пользователя ≤ 5 минут.
- Доля наград с действиями; доля доставленных звуков; возвраты и ошибки на 100 активаций.
- Задержка алерта (p95), дропы очереди.
- Использование TTS, панели и хоткеев; удержание 7/30 дней; краши на сессию.

## 16. Вопрос

Что прототипировать первым?

- **A. Алерты** — самый заметный для зрителя результат, умеренная сложность.
- **B. Движок действий + три действия** — архитектурный фундамент, но дольше до видимого результата.
- **C. TTS** — сильный дифференциатор, полностью локальный.
- **D. OBS-мост** — пульт и клипы, но зависит от настройки OBS.
- **E. Безопасность звука (v1.8)** — меньше всего риска, но не так заметно.

Рекомендация: **A + C в одном релизе** (алерт с озвучкой) — это самый заметный для зрителя результат при умеренной сложности; движок действий — сразу после, он их объединит.
