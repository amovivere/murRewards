## 2. Экраны и что на них реально работает

* Работают: счётчики в пилюлях и подзаголовок (`app.js:519-550`), статус Twitch в шапке (`app.js:65-94`), ссылка «Открыть в „Музыке“» для музыкальной награды (`app.js:684-687`).

### 2.6. Каркас окна, трей
* Кастомный заголовок (`index.html:39-47`), drag через `win.startDragging()` (`app.js:116-127`) — работает при `withGlobalTauri` и разрешении `core:window:allow-start-dragging`.
* Кнопки «свернуть/развернуть/закрыть» **не работают** (см. 1.2). Закрыть окно можно только Alt+F4 / трей-меню / завершением процесса.
* Трей: меню «Открыть/Выход», double-click/left-click показывает окно (`main.rs:78-107`); single-instance — TCP-порт 47831 (`main.rs:20-23`); close-to-tray обрабатывается в Rust (`main.rs:66-76`), но флаг читается **один раз при старте** (`main.rs:34-35`).
* `start_minimized` — окно скрывается при старте (`main.rs:112-117`). Переключатели в настройках сохраняются, но на текущий сеанс не влияют до перезапуска — UI об этом не сообщает.

## 6. Ошибки и статусы: как показываются

* **Twitch.** Ошибка входа/токена — `auth.error` в настройках (`app.js:1249`) и `rewards_error` в тосте/пустой сетке (`app.js:567,582`). Причина обрыва EventSub — нет (`eventsub_error` не выводится); статус ограничен «Слушаем/Переподключение…/Не слушаем» (`app.js:69-83`) плюс автоматический реконнект внутри `eventsub.rs`.
* **Награды.** Ошибка `fetch_rewards`/управления наградой → `inner.error` → тост на 6 с и текст в пустой сетке; отдельной кнопки «Повторить» нет (только иконка «Обновить», `app.js:712-724`). Ошибки `create/update/delete` при этом затираются успешным тостом (П19–П20).
* **yt-dlp/музыка.** `MusicService` кладёт причину в лог (`Failed/Rejected`), в UI — ничего: `music.error`/`player.error` не читаются; отклонённая заявка исчезает из очереди (фильтр финальных состояний). «yt-dlp не найден» показан пилюлей (`app.js:870-879`) и в карточке состояния, но кнопки ре-чека/пути нет.
* **Аудио.** `preview_sound`/`stop_all_sounds` возвращают `()`, ошибки проглатываются, тост всегда успешный (П21). «Звук готов» — константа.
* **Сохранение настроек.** Индикатора нет; тумблеры сохраняются молча (П24), ошибка `set_app_setting` видна только в футере как `IPC error: …`.
* **Подтверждения.** Есть только удаление награды через `window.confirm` (П22). Нет подтверждений: отключение Twitch, очистка очереди, удаление заявки, удаление привязки звука, выход.
* **Футер как единственный канал статуса** (`app.js:41-50`): автосброс «Готово» через 4,5 с; перекрывается следующей операцией; `IPC error` в нём — технический текст для пользователя.
* **Журнал** — фактически единственное место, где видны причины ошибок музыки/Twitch (WARN/ERROR), но он не автообновляется и общий с egui-приложением.

## 7. Несоответствия и риски

### 7.1. Функциональные разрывы и ложные обещания
1. **Окно нельзя закрыть/свернуть/развернуть из UI** — главный функциональный блокер (П1). При этом `capabilities/default.json` уже разрешает minimize/toggle-maximize/close/start-dragging — не хватает только правильных JS-вызовов.
2. **OBS-настройки — фикция**: модалка показывает 10/17/top, поля не сохраняются, «Открыть в браузере» — заглушка; бэкенд-настройки `overlay_*` существуют, но недоступны (П12–П13).
3. **Онбординг обещает больше, чем делает**: «Проверить звук» отсутствует, «Локальные привязки · 9» и аудиоустройство — вымысел, «0 из 3» не двигается. Пользователь впервые запускает приложение и видит фейковые данные (П14–П16).
4. **Карточка «Состояние» музыки утверждает факты, которые не проверяет**: «Порт 8770 — свободен», «Чат: !трек работает» (при незаполненном канале чат вообще не стартует — `chat.rs:26-30`; после входа в Twitch канал в music-service не переотправляется, кроме `configure` при переключении приёма заявок/новых командах).
5. **Кнопки «···»/«Изменить»** выглядят интерактивно (есть hover-курсор, `app.css:114-117`), но мертвы.
6. **`RewardView` не отдаёт `requires_input`** → редактирование любой награды, требующей ввода текста (кроме музыкальной), молча снимает флаг (П9) — это потеря данных на Twitch.
7. **Нельзя включить/выключить/приостановить награду, изменить порядок** — бэкенд-команды отсутствуют, `update_body` не шлёт `is_enabled` (`twitch.rs:188-197`), а UI прячет недоступные награды. При этом `sort_rewards_for_display` в библиотеке уже сортирует доступные сверху (`twitch.rs:125-127`).
8. **Переключатели `close_to_tray`/`start_minimized`** сохраняются, но текущий сеанс не меняют (флаги прочитаны один раз, `main.rs:34-35,66-76`) — без предупреждения в UI.
9. **`music_set_enabled`** при включении вызывает `set_paused(!enabled)` → может неожиданно возобновить воспроизведение; при выключении только ставит на паузу (в базовом core).
10. **`open_url` allowlist** не пускает `http://127.0.0.1:8770` — «Открыть в браузере» требует отдельного пути.

### 7.2. Данные и состояние
11. Ошибки IPC глотаются (`app.js:10-21`) → часть операций показывает успех при провале (П19–П21); `try/catch` в местах вызова бесполезен.
12. `get_state` — синхронная команда с блокирующим ожиданием до 2,5 с; `choose_sound` — синхронная команда с модальным `rfd`-диалогом: риск подвисания интерфейса/очереди IPC, пока открыт диалог (нужен `async`/`spawn_blocking`).
13. Двойной опрос `get_state` (П29) + полная перерисовка сетки/очереди/настроек каждые 1,5 с: DOM-churn, потеря фокуса в настройках (П25), лишняя нагрузка.
14. Кэш файлов строится один раз при старте (`build_file_cache`, `core.rs:878`): если файл удалили/переместили, UI продолжает показывать «существует», пока не выберут файл заново/не перезапустят.
15. **Конкурентность с egui-версией**: у Tauri single-instance через TCP-порт 47831 (`main.rs:20-23`), у egui — именованный мьютекс `Local\RewardSoundsSingleInstance` (`reward-sounds/src/main.rs:120-150`); оба могут работать одновременно. Общие: `%APPDATA%\RewardSounds\config.toml`, `logs\reward-sounds.log`, порт оверлея 8770, аудиоустройство, подписки EventSub (двойное проигрывание звуков при активации, гонки записи конфига). В README/UI нет предупреждения.
16. `state.connected` по умолчанию `true`, демо-название `goshanmur`, `musicTitle` — до/при неудачном `get_state` UI показывает мок-данные, не ошибку.

### 7.3. Вёрстка/внешний вид
18. Базовый `style.css` жёстко задаёт 1220×840 (`style.css:5,8`) — перекрыто в `app.css:5-6`; корректно, но любой новый экран нужно проверять на 980×680.
19. **При 980×680 риск переполнения**: карточка OBS (55 % от контента ≈ 350 px) содержит URL в monospace (~200 px) + кнопку-копию + «Показать сейчас» без `flex-wrap` — суммарно ~370–390 px, вероятен выход за карточку/сжатие кнопки; карточка «Состояние» (45 %) с фиксированной высотой 128 px и `overflow:hidden` может обрезать текст при длинных подписях; онбординг не имеет media-query — правая колонка 38 % ≈ 260 px с двумя карточками может стать тесной; музыкальный плеер: 102 px обложка + 196 px колонка громкости оставляют ~330 px на название/управление (спасает ellipsis).
