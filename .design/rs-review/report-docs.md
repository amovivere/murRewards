## 0. Кратко для решения

1. **README и `КАК ЗАПУСТИТЬ.txt` описывают приложение до появления музыки.** В них нет ни одного упоминания «Музыка», «OBS», «yt-dlp», «YouTube», «очередь» (проверено grep по README — 0 совпадений). При этом в коде есть целый модуль `src/music/` (11 файлов, ≈3100 строк) и вкладка «Музыка» (`src/app.rs:1271`, `src/app.rs:2834`).
2. **Сборка в `dist` устарела и не соответствует ни README, ни исходникам.** `dist\Reward Sounds.exe` от 11.11.2026 00:33: в бинарнике **нет** строк «Музыка», «yt-dlp», «Оверлей», «Слушаем заявки»; `target\release\reward-sounds.exe` от 15.11.2026 02:55 — есть. README (§2) отправляет пользователя запускать именно `dist`, то есть пользователь получит 1.6.2 без музыки. Это разрыв «релиз — документация — исходники».
3. **Версия не поднята.** Музыка, OBS-оверлей и новая чёрная тема появились 14–15.11 (mtime `src/music/*`: 14.11; `src/theme.rs`: 14.11 20:22; `src/app.rs`: 14.11 23:50), а `Cargo.toml` всё ещё 1.6.2. Нет `CHANGELOG.md` (в проекте всего два текстовых файла — README и КАК ЗАПУСТИТЬ).
4. **Скриншоты устарели все 5.** Старая фиолетовая тема, старый сайдбар без подписей, разные версии в подвале (1.6.0 и 1.6.2), `twitch-login.png` вообще из другой компоновки (верхние вкладки «Звуки/Награды/Настройки/Журнал», 1090×800). `docs/settings.png` при этом **не используется в README**.
5. **Прямые фактические ошибки в README:** «Доступ только на чтение наград» (на самом деле запрашиваются `channel:read:redemptions` **и** `channel:manage:redemptions`, `src/twitch.rs:22`); «Сторонние программы не нужны»/«работает без лишних программ» (музыке нужен внешний `yt-dlp.exe`); «системные шрифты Windows» (шрифт Inter встроен, `src/theme.rs:38-40`); «GOSHAN MUR вместо иконки R» (в коде снова «R» + «Reward Sounds», `src/app.rs:1240-1259`); «в настройках — строка „Активации наград: Слушаем награды“» (в UI это две отдельные подписи, `src/app.rs:2353`, `:2355`).
6. **Онбординг не покрывает новый сценарий.** Максимальный провал — вкладка «Музыка» при первом запуске: чекбокс «Включено» уже включён, статус может гореть зелёным «Слушаем заявки» (`src/app.rs:2848-2854`) без выбранной награды и без Twitch, а `yt-dlp.exe` в `dist` не поставляется вовсе — пользователь видит красное «Нет yt-dlp» и тупик без ссылки, без кнопки «скачать», без объяснения, что это.
7. **Терминология «плывёт»:** «Стоп» / «Остановить все звуки» / «Остановить всё»; «Убрать» / «Убрать звук»; «Заменить» / «Заменить звук»; «Прослушать» / «Проверить звук»; «ГРОМКОСТЬ» / «Громкость» / «ЗВУК»; «нажми» на «вы»-интерфейсе (`src/app.rs:2945`); «1.0» в карточке «О программе» (`src/app.rs:2722`).
8. **Ключевые продуктовые дыры онбординга:** нет чек-листа первого запуска, нет тестовой активации награды (кнопка «Прослушать» играет напрямую через аудиодвижок, минуя EventSub — `src/app.rs:1403`, то есть не проверяет сквозной сценарий), нет демо-звука, нет ссылки «где взять yt-dlp», в подсказке музыки написано «Путь к yt-dlp — в карточке „Состояние“» (`src/app.rs:3113`), а поля пути в этой карточке нет (`src/app.rs:3130-3148`).

### 4.2 Чего не хватает в `КАК ЗАПУСТИТЬ.txt`

1. **Музыка вообще не упомянута.** Нет ни слова про вкладку «Музыка», yt-dlp, OBS-оверлей, очередь, `!трек`.
2. **Нет требований к системе:** Windows 10/11 x64, права пользователя (админ не нужен), интернет для Twitch, отдельно интернет для YouTube-музыки.
3. **Нет про yt-dlp:** что это, где взять, куда положить (`рядом с exe` / `tools\` / `%APPDATA%\RewardSounds\tools` / `PATH`, `src/music/ytdlp.rs:91-128`), как проверить (красный/зелёный статус `src/app.rs:2848-2854`).
4. **Нет про антивирус:** Defender/сторонние AV могут ругаться на неподписанный exe и на `yt-dlp.exe`; как добавить в исключения; где взять официальный yt-dlp (github releases), как проверить, что приложение не публикует данные (оно их не публикует, но проверить нечем — можно указать, что все данные локальны).
5. **Нет про один экземпляр:** повторный запуск не создаёт второй процесс, а показывает уже открытое окно (`src/main.rs:29-32`, `:108-133`, `:142-144`). Пользователю это полезно знать (два раза кликнул — «ничего не произошло»).
6. **Нет про портативный режим** (`REWARD_SOUNDS_DATA_DIR`, `src/config.rs:499-507`) и про то, что автозапуск его не сохраняет (`src/autostart.rs:130-133`).
7. **Нет про перенос папки:** после переноса сбрасывается автозапуск (`src/app.rs:168`), а старые настройки остаются в `%APPDATA%` — нужно или перенести данные, или включить портативный режим.
8. **Нет «что делать, если уже запущено»** — см. п. 5; нет «как полностью закрыть» (только меню трея «Выход», `src/tray.rs:318`; кнопка закрытия окна сворачивает в трей).
9. **Нет данных:** где настройки/журнал (`%APPDATA%\RewardSounds`, `src/config.rs:482-523`, `src/logging.rs:2-4`), как открыть (Настройки → «Данные приложения», `src/app.rs:2690-2711`), какие файлы бэкапов появляются (`src/config.rs:397-401`, `:433-436`).
10. **Нет «как удалить»:** удалить папку программы + `%APPDATA%\RewardSounds` + значение `RewardSounds` в `HKCU\...\Run` (или выключить автозапуск и выйти из трея).
11. **Нет проверки после настройки:** «проверьте звук», «проверьте активацию» (см. §2.5).
12. **Нет предупреждения про `dist`:** файл советует открыть `dist`, но именно там может лежать неактуальная сборка (сейчас — да).

7. ТРЕЙ, АВТОЗАПУСК, ЗАКРЫТИЕ

### 5.4 Что обязательно должно быть в разделе «Музыка»

1. **Схема работы:** награда с вводом текста → зритель вставил ссылку → EventSub → проверка ссылки (`src/music/links.rs`) → метаданные через yt-dlp (`src/music/ytdlp.rs:150-172`) → очередь (`src/music/queue.rs`) → плеер (`src/music/player.rs`) → оверлей (`src/music/overlay.rs`).
2. **Требования:** `yt-dlp.exe` (где взять, куда положить, как проверить: статус + «Состояние» → «yt-dlp {версия}», `src/app.rs:3132`), награда с обязательным вводом текста (ставится автоматически при выборе, `src/app.rs:3471-3488`), оба права Twitch.
3. **Пошаговая настройка (5 шагов)** с 2–3 скриншотами.
4. **Очередь:** «Очередь · N», «Убрать», «Выше», «Очистить очередь», «Сыграно» + повтор «↻», лимит 1–50 (`src/app.rs:3067-3077`).
5. **Плеер:** «С начала», «Пауза/Продолжить», «Пропустить», перемотка, отдельная громкость (`src/app.rs:3250-3405`).
6. **Лимиты:** длительность 1–120 мин (дефолт 8 мин, `src/config.rs:95`, `src/app.rs:3082-3091`); только YouTube (youtu.be, youtube.com/watch, /shorts, /live, /embed, m., music.; клипы и плейлисты — нет, `src/music/links.rs:61-108`); эфиры и не-YouTube отклоняются (`src/music/queue.rs:152`, `:43`).
7. **Возврат баллов:** засчитано — сыграно; возвращены — отклонено/ошибка/пропущено (`src/app.rs:815-852`, `src/twitch.rs:267-288`).
8. **OBS-оверлей:** URL `http://127.0.0.1:8770/overlay`, источник «Браузер», 1920×200–300, отключить автообновление/автоотключение, секунды показа (0 — показывать постоянно), размер шрифта, сверху/снизу, `!трек` (`src/app.rs:3152-3164`, `:3177-3247`, `src/music/overlay.rs:16`), предупреждение про занятый порт.
9. **Яндекс Музыка:** пауза через медиа-сессии Windows (`src/music/yandex.rs`, настройка `pause_yandex`, `src/app.rs:3096-3108`).
10. **Что увидит зритель:** 3 шага + пример prompt «Вставьте ссылку на трек из YouTube».
11. **Ограничения/дисклеймер:** YouTube ToS, авторские права, трек может не загрузиться (блокировка/регион/возраст) — баллы вернутся; yt-dlp может требовать обновления при изменениях YouTube (автообновления в приложении нет — настройка `ytdlp_update_days` не реализована, `src/config.rs:69`, вызовы `YtDlp::update` отсутствуют).
12. **Чего нет:** сохранения очереди между запусками (очередь в памяти, `restore_queue` не используется — `src/config.rs:76`), выбора устройства вывода для музыки (общее устройство Windows).

### 5.5 Глоссарий (в README приложением)

| Термин | Объяснение |
|---|---|
| Награда (reward) | Пользовательская награда канала Twitch за баллы |
| Баллы канала (Channel Points) | Внутренняя валюта канала; зритель тратит на награду |
| Активация / redemption | Момент, когда зритель потратил баллы на награду |
| Client ID | Публичный идентификатор приложения Twitch (не пароль) |
| Client Secret | Секрет приложения; **не нужен** и не хранится |
| Device Code Flow | Вход по короткому коду на twitch.tv/activate |
| EventSub | Канал событий Twitch (WebSocket), по нему приходят активации |
| Скоуп (scope) | Право доступа: `channel:read:redemptions`, `channel:manage:redemptions` |
| Заявка | Просьба зрителя поставить трек (награда + ссылка) |
| Трек | Аудио, которое играет в разделе «Музыка» |
| yt-dlp | Отдельная программа для скачивания аудио с YouTube; нужна для музыки |
| Оверлей | Строка «Сейчас играет» поверх стрима; в OBS — источник «Браузер» |
| DPAPI | Шифрование Windows, привязанное к учётной записи |
| Портативный режим | Данные рядом с программой через `REWARD_SOUNDS_DATA_DIR` |

## 9. Twitch API: ограничения, токены, персональные данные

### 9.1 Права (скоупы) — что и зачем

| Право | Зачем приложению | Где используется |
|---|---|---|
| `channel:read:redemptions` | Читать награды и получать события активаций через EventSub | `src/twitch.rs:22`, `src/eventsub.rs:25`, `:362-451` |
| `channel:manage:redemptions` | Создавать/изменять/удалять награды; засчитывать/отменять активации (возврат баллов) | `src/twitch.rs:842`, `:929-983`; `src/app.rs:859-880` |

Формулировка для README: «Приложению нужны два права: **читать награды и активации** и **управлять наградами** (создание, изменение, удаление, зачёт/возврат баллов). Пароль не запрашивается. Client Secret не нужен». Если аккаунт подключался в 1.6.x (только чтение), управление наградами и музыка не работают, пока не переподключить — приложение пишет об этом (`src/app.rs:587`, `:592`).

### 9.2 Что Twitch API не позволяет (и как это объяснить)

1. **Обложку награды нельзя загрузить/изменить через API.** Twitch принимает картинку только в панели наград. Приложение открывает `https://dashboard.twitch.tv/community/channel-points/rewards` (`src/app.rs:23`, `:1683`). В README:142 — верно, оставить и усилить: «даже если очень хочется — API этого не умеет, кнопка „Панель наград Twitch“ открывает нужную страницу».
2. **Ограничения полей:** название ≤ 45 символов (`src/twitch.rs:162`), цена 1–1 000 000 (`:165`), цвет `#RRGGBB` (`:168`). Ошибки показывает и приложение (`:160-170`).
3. **Управление доступно только для пользовательских наград канала**, а не для наград других каналов/глобальных.
4. **Статусы активации** бывают `FULFILLED` / `CANCELED`; отменить уже зачтённую активацию нельзя — Twitch вернёт ошибку. Приложение рассчитывает, что успевает отменить до зачёта; в README стоит написать: «если трек не сыграл, баллы обычно возвращаются автоматически».
5. **Rate limits:** у Helix есть лимиты; приложение не опрашивает Twitch в цикле — обновление только по кнопке/после входа (`src/app.rs:652-700`), EventSub работает по WebSocket. В доках не нужно пугать цифрами, но стоит написать «не нажимайте „Обновить“ десятки раз подряд».
6. **EventSub событие может прийти повторно** после переподключения — приложение отбрасывает дубли по ID (`src/eventsub.rs:313`, `src/music/service.rs:330-345`). Для документации: «повторные события не приводят к двойному звуку/двум заявкам».

### 9.4 Персональные данные и журнал

Что реально хранится/пишется (важно для раздела «Приватность»):
- `config.toml`: Twitch user id/login/display name, зашифрованные токены, **локальные пути к файлам звуков** (`src/config.rs:14-27`, `:130-143`), настройки музыки; `client_id` открытым текстом.
- Журнал: `@логины` зрителей и названия наград в событиях активаций (`src/app.rs:770`, `src/app.rs:789`, `src/music/queue.rs`), пути к файлам при ошибках (`src/app.rs:1388`), адреса/ошибки сети. Это персональные данные зрителей (ники) — журнал не стоит публиковать целиком.
- Очередь музыки сейчас **не сохраняется** на диск (см. §6.2), поэтому между запусками история заявок не хранится.
- Временные файлы yt-dlp — в `%APPDATA%\RewardSounds\tmp` (`src/music/ytdlp.rs:224-227`): там могут оставаться фрагменты аудио; чистить вместе с данными приложения.
- Оверлей отдаёт по `http://127.0.0.1:8770/overlay` и `/state` название трека, канал, **логин заказавшего** и очередь (`src/music/overlay.rs:44-118`). Слушает только localhost: прочитать данные может любой локальный процесс; веб-страница в браузере может отправить запрос, но прочитать ответ без CORS-заголовков не сможет (их нет). В README: «оверлей доступен только на этом компьютере».

Рекомендуемый текст для README (раздел «Данные и приватность»):
> Reward Sounds не отправляет телеметрию и не загружает ваши файлы в интернет. Наружу уходят только запросы к Twitch (вход, награды, события) и — в режиме музыки — запросы yt-dlp к YouTube по ссылке зрителя. Настройки, журнал и токены хранятся локально в `%APPDATA%\RewardSounds`. Токены зашифрованы Windows DPAPI и не переносятся на другой компьютер. Журнал содержит ники зрителей и названия наград — не публикуйте его без необходимости. Удалить все данные: выйти из трея, удалить `%APPDATA%\RewardSounds` и значение `RewardSounds` в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`.

### 9.6 Безопасность yt-dlp и ссылок

- Ссылка зрителя **нормализуется** в канонический `https://www.youtube.com/watch?v=<id>` (`src/music/links.rs:111-133`), поэтому подставить флаги yt-dlp через текст заявки нельзя; аргументы передаются массивом (`src/music/ytdlp.rs:245-256`).
- Скачивание идёт в память, с лимитом размера (`src/music/ytdlp.rs:174-203`), таймаутами (`:281-283`).
- `yt-dlp.exe` — сторонний неподписанный бинарник; рекомендация в доках: скачивать только с официального GitHub-релиза, проверять, что антивирус не подменил файл.

### 9.7 Ограничения, которые надо явно проговорить в README

1. Нет выбора аудиоустройства — только устройство Windows по умолчанию (`src/app.rs:2585`).

3. У музыки очередь есть, но **не сохраняется** между запусками.
4. Обложки наград — только через панель Twitch.
5. Музыка требует внешний yt-dlp и интернет к YouTube.
6. `!трек` требует, чтобы чат-листенер был запущен с известным каналом (см. П-13).
